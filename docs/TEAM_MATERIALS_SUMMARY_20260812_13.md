# 8월 12–13일 팀 자료 종합 정리

## 1. 이틀간의 핵심 결론

- 서비스 이용 범위는 만 19세 이상으로 열어두되, 주 타깃과 화면 접근성의 기준은 만 65세 이상 고령자로 설정한다.
- 우선 예측 질환은 당뇨병과 고혈압이다.
- 모델 결과는 진단이 아니라 현재 위험 선별과 건강교육으로 표현한다.
- KNHANES는 검진·생활습관 기반의 현재 위험 선별에, KLoSA는 다음 조사차수의 신규 진단과 종단 변화 분석에 활용한다.
- 두 데이터셋은 참여자나 행 단위로 직접 합치지 않고, 공통 변수의 의미·단위·결측 규칙·역할을 통합 메타데이터로 연결한다.
- 8월 13일까지 요구사항 정의서, 와이어프레임, ERD, API 명세서, AI·데이터 계획의 v1.0 초안이 마련되었다.

## 2. 8월 12일 진행 내용

### 정세준 — PM·기획·문서·QA

- 기업 필수·선택 기능을 요구사항 ID로 구조화했다.
- 기능·비기능 요구사항, 우선순위, 수용 기준을 포함한 요구사항 정의서 초안을 작성했다.
- 주 타깃은 65세 이상으로 두되 학습 데이터는 19세 이상까지 활용하고, 19세 이상·40세 이상·65세 이상 모델을 비교하는 방향을 정리했다.
- KLoSA와 KNHANES의 역할 및 결합 원칙, AI허브 데이터·제공 모델의 활용 범위를 정리했다.
- 위험도 변화 계산, 재예측, 챌린지 사이클, 기진단자 처리 등 ERD 정책을 요구사항과 화면 흐름에 반영했다.

### 양준혁 — AI·데이터·모델

- KLoSA와 KNHANES 중 모델 목적에 맞는 자료를 비교하고 고혈압·당뇨 관련 변수 후보를 추렸다.
- 1차 예측 문제와 타깃 라벨 후보를 검토했다.
- 다음 단계에서 공식 생성변수, 입력 가능 변수, 누수 변수, 연령별 코호트를 구분할 수 있는 기반을 마련했다.

### 이수인 — 프론트엔드·UI/UX

- A-1 주 페르소나와 보조 페르소나를 기준으로 사용자 흐름을 정리했다.
- 기본 흐름을 `서비스 소개 → 접근성 지원 → 회원가입·동의 → 적합성 확인 → 검진자료 확인 → 건강정보 입력 → 위험 결과 → 위험·보호 요인 → 챌린지 → 일일 기록 → 대시보드`로 구성했다.
- 부적합, 고위험, 검진자료 미보유, 기진단 사용자의 예외 흐름을 분리했다.
- 필수 화면 16개, 페이지별 목적·입력·출력·다음 화면, DB·API 필요 데이터를 정리하고 Figma 흐름도 초안을 제작했다.

### 박빛샘 — 백엔드·DB·인프라

- dbdiagram 기반 ERD 초안을 작성했다.
- 핵심 엔터티의 PK·FK와 1:1·1:N 관계를 표시하고, 계정정보와 건강정보를 분리했다.
- HealthCheckup–Prediction 관계와 ChallengeCycle 중심의 4주 챌린지 구조를 반영했다.
- 확정·가정·추가 확인 사항을 분리해 팀 투표가 필요한 안건으로 정리했다.

### 전처리 공유 결과

- KLoSA 1–10차와 KNHANES 2016–2024년 원자료를 공식 코드북 기준으로 전처리했다.
- 정제 전 기준 KNHANES 67,019건, KLoSA 74,834개 패널 관측행이며 중복 키는 0건, 전처리 테스트 11개가 통과했다.
- KNHANES는 19세 이상·40세 이상·65세 이상 코호트와 연도 기반 분할(train 2016–2020, validation 2021–2022, test 2023–2024)을 구성했다.
- KLoSA는 PID 그룹 분할로 동일 대상자가 서로 다른 split에 섞이지 않도록 했다.
- 혈압·혈당·HbA1c·진단·복약·공식 질환상태 등 정답을 직접 결정하거나 강하게 노출하는 변수는 모델 입력에서 제외했다.
- 결측 대치·스케일링·범주 인코딩은 전체 데이터에서 미리 학습하지 않고 train split에서만 적합하도록 했다.
- 원자료와 행 단위 정제 자료는 GitHub에 올리지 않고 재현 코드, 변수 명세, 무결성 기록, 집계 품질보고서, 전처리 프로토콜만 공유하기로 했다.

## 3. 8월 13일 진행 내용

### 정세준 — 문서 통합·멘토링 준비

- 요구사항 정의서 v1.0을 기준으로 기능 범위와 우선순위를 점검했다.
- 와이어프레임·ERD·API·AI 계획 간 표현과 추적 관계를 검토했다.
- 8월 14일 멘토링을 위한 회의 결과 및 사전보고서를 작성하고, 확정 사항과 피드백 요청 사항을 구분했다.

### 양준혁 — 당뇨 타깃·실험 설계

- KNHANES 2019–2024의 `HE_DM_HbA1c`를 기준으로 정상 0, 전당뇨 1, 당뇨 2의 현재 상태 라벨을 정리했다.
- 유효 표본 33,000명은 정상 15,393명(46.65%), 전당뇨 12,364명(37.47%), 당뇨 5,243명(15.89%)으로 확인했다.
- 직접 3클래스 다중분류와 세 가지 이진분류를 비교했다.
  - 정상 vs 전당뇨: 초기 위험 탐색용 보조 모델
  - 정상·전당뇨 vs 당뇨: 검사·상담 우선 권고를 위한 핵심 이진모델 후보
  - 정상 vs 당뇨: 전당뇨가 제외되므로 운영보다 벤치마크용
- Logistic Regression, Random Forest, XGBoost 또는 LightGBM을 베이스라인 후보로 선정했다.
- AUROC, AUPRC, Macro F1, 클래스별 Recall, 민감도·특이도, 혼동행렬, Brier score, Calibration curve를 평가 후보로 정리했다.
- 타깃·혈당검사·진단·치료·복약·진단시기·예측 이후 정보 등 누수 변수를 제외하도록 정리했다.

> 표본 수 주의: 33,000명은 공식 당뇨 상태가 유효한 전체 표본의 분포이고, 전처리 공유 문서의 당뇨 모델 코호트는 기진단자를 제외한 위험 선별 대상자다. 목적과 포함 기준이 달라 수치가 다르므로 같은 모집단으로 비교하면 안 된다.

### 이수인 — 기능 확정·Mid-Fi 와이어프레임

- 구현 기능을 필수와 후순위로 구분하고 각 기능에 필요한 화면을 연결했다.
- 사용자 흐름의 누락과 중복을 점검하고 Mid-Fi 와이어프레임 초안을 작성했다.
- 우선 화면은 서비스 소개, 가입·동의, 적합성 확인, 건강정보 입력, 예측 진행·결과, 위험·보호 요인, 챌린지, 대시보드, 의료기관 안내, 마이페이지로 정리했다.
- 본문 18px 이상, 버튼 최소 44×44px, 높은 명암비, 한 화면 한 가지 핵심 행동, 색상+텍스트·아이콘 병행, 쉬운 의료용어 등 고령자 접근성 기준을 구체화했다.
- 기진단자는 위험 예측을 생략하고 의료진 지침 우선 안내와 함께 챌린지로 연결하는 흐름을 검토했다.

### 박빛샘 — ERD 확정·FastAPI/API 구조

- ERD 투표를 마감하고 확정·미확정 안건을 구분해 수정 ERD에 반영했다.
- FastAPI를 API·Service·Repository·Domain·ML 계층으로 나누는 구조를 정리했다.
- 인증·동의·적합성·건강검진·예측·챌린지·대시보드·후속조치·추천·피드백 API 영역을 정의했다.
- `/api/v1` 버전 프리픽스, `/users/me/...` 자원 경로, JWT 인증, 자원 소유권 검사, 공통 오류 형식, 페이지네이션, 멱등성, 비동기 예측 작업을 반영했다.
- 예측 요청은 `202 + job_id`를 반환하고 `pending/done/failed` 상태를 조회하는 방식으로 설계했다.
- 이미 예측에 사용한 건강검진 기록은 수정하지 못하게 하고 새 기록을 만들도록 하며, 동일 날짜·챌린지 로그 중복은 409로 처리하기로 했다.

## 4. 이틀간 확정된 공통 정책

| 영역 | 결정 내용 |
| --- | --- |
| 대상 | 서비스 이용은 만 19세 이상, 주 타깃과 접근성 기준은 만 65세 이상 |
| 질환 | 당뇨병·고혈압 우선 구현 |
| 데이터 역할 | KNHANES는 현재 위험 선별, KLoSA는 다음 차수 신규 진단·종단 변화 |
| 데이터 결합 | 행 단위 결합 금지, 통합 메타데이터로 의미·단위·결측·역할 연결 |
| 예측 이력 | 건강검진 1건에 여러 모델 버전의 예측을 허용하고 최신 결과를 표시 |
| 위험도 변화 | 최초 대비 변화값은 별도 저장하지 않고 조회 시 계산 |
| 챌린지 | ChallengeCycle을 별도 엔터티로 관리하고 최대 3개 챌린지를 한 요청으로 시작 |
| 기진단 확인 | 위험 예측을 제공하지 않으며 진행 중 챌린지는 중단 상태로 보존, 과거 기록은 삭제하지 않음 |
| 후속 권고 | 적합성 확인 또는 예측 결과 중 발생 출처를 저장 |
| API | `/api/v1/users/me/...` 중심, 인증·소유권·공통 오류·비동기 예측 적용 |
| 의료 안전 | 진단·처방이 아니라 위험 선별·교육으로 표현하며 의료진 지침을 우선 안내 |

## 6. 남은 핵심 논의사항

- 운영 기준을 직접 3클래스 분류로 할지, 핵심 이진모델과 보조·벤치마크 모델을 병행할지 확정한다.
- 고혈압 타깃의 공식 정의, 표본 수, 누수 제외 변수표를 당뇨와 같은 수준으로 완성한다.
- 기진단 사용자에게 챌린지를 제공할 범위와 첫 화면·대시보드 문구를 확정한다.
- 당뇨병·고혈압의 단계와 클래스 확률을 공통 Prediction 구조에 저장하는 방식을 확정한다.
- PredictionJob 엔터티와 모델 버전·상태·실패 사유의 저장 범위를 확정한다.
- 개인정보·건강정보의 암호화, 보관기간, 탈퇴·동의 철회 시 삭제·익명화 정책을 확정한다.
- 요구사항–화면–API–ERD–테스트 간 ID 추적표를 완성한다.
