# KLoSA·KNHANES 전처리 프로토콜

## 1. 목적과 범위

고혈압·당뇨병 위험 선별 모델을 위해 KLoSA와 국민건강영양조사(KNHANES)를 각각 전처리한다. 두 조사는 조사설계와 타깃 시점이 다르므로 참여자 행을 직접 결합하지 않는다. 공통 변수의 의미, 단위, 결측 규칙, 역할을 `official_selected_variable_registry.csv`로 연결한다. KNHANES는 19+/40+/65+ 모델을 비교하고 KLoSA는 단일 패널 모델로 구성한다.

모델 결과는 진단·처방이 아니라 위험 선별과 건강교육에만 사용한다.

현재 Sprint 2의 우선 구현 질환은 당뇨병이다. 고혈압 전처리 경로는 동일한 인터페이스로 후속 확장할 수 있도록 유지하며, 서비스에 노출하기 전 별도 모델 검증을 거친다.

## 2. 입력 자료

| 자료 | 범위 | 관측 구조 | 주된 용도 |
| --- | --- | --- | --- |
| KNHANES | 2016–2024년 | 매년 다른 표본의 반복 횡단면 | 검사·설문 기반 현재 임상 위험 선별 |
| KLoSA | 1–10차, 2006–2024년 | 동일 PID 반복 패널 | 인접 다음 차수의 신규 진단 위험 예측 |

원본 압축파일과 추출 원자료는 각각 `data/raw/`, `data/interim/source_extract/`에 두며 Git에서 제외한다. 실행할 때 원본 압축파일의 파일명·크기·SHA-256을 `data/metadata/official_raw_source_manifest.csv`에 기록한다.

## 3. 타깃 정의

### KNHANES

- 고혈압: 공식 파생변수 `HE_HP` 사용
  - 2016–2021년: 1 정상, 2 고혈압 전 단계, 3 고혈압 → `3`을 양성으로 정의
  - 2022–2024년: 1 정상, 2 주의혈압, 3 고혈압 전 단계, 4 고혈압 → `4`를 양성으로 정의
- 당뇨병:
  - 2016–2018년: `HE_DM`의 `3`을 양성으로 정의
  - 2019–2024년: HbA1c를 포함한 `HE_DM_HbA1c`의 `3`을 양성으로 정의
- 미진단 위험군 모델은 해당 질환의 의사진단 문항이 명시적으로 `아니오`이며 공식 질환상태 타깃이 관측된 19세 이상만 포함한다.

### KLoSA

- 1차와 5차 신규표본의 `C006`, `C011`은 기준시점 진단 이력으로 사용한다.
- 이후 차수의 같은 문항은 직전 기본조사 이후 신규 진단 사건으로 사용한다.
- 기준 차수까지 모든 질환 문항이 관측되고 진단 이력이 없으며, 바로 다음 인접 차수에 응답한 경우만 학습 대상이다.
- 타깃은 다음 인접 차수의 고혈압 또는 당뇨병 신규 진단 여부다. 차수 간격은 약 2년이다.

## 4. 데이터 누수 방지

다음 항목은 타깃 구성·적합성 확인·감사에만 보존하며 모델 입력에서 제외한다.

- 수축기·이완기 혈압
- 공복혈당, HbA1c
- 고혈압·당뇨병 진단 및 복약 변수
- 공식 질환상태 파생변수
- 현재 및 과거 질환사건 변수

결측치 대치, 스케일링, 범주 인코딩은 정제 파일 생성 단계에서 수행하지 않는다. 모델 학습 시 train split에서만 변환기를 적합하고 validation/test에는 변환만 적용한다.

## 5. 분석 집단과 데이터 분할

- KNHANES는 19세 이상, 40세 이상, 65세 이상 코호트를 각각 산출한다.
- KLoSA는 조사 모집 특성상 연령 코호트로 분리하지 않고 전체 적격 패널 표본을 사용한다.
- KNHANES: train 2016–2020, validation 2021–2022, test 2023–2024의 시간 분할
- KLoSA: PID 해시 기반 그룹 분할로 동일 참여자가 서로 다른 split에 들어가는 것을 방지
- KNHANES 3개 모델의 일반 성능과 함께 공통 65+ test에서의 성능·보정·재현율을 비교한다.

## 6. 결측·범위 처리

- 범주형은 공식 허용 코드만 남기고 그 외 응답, 거절, 모름, 비해당을 결측으로 처리한다.
- 연속형은 변수별 단위와 임상적으로 가능한 넓은 감사 범위를 적용한다.
- `8`, `9`, `88`, `99` 등을 전체 변수에 일괄 결측 코드로 적용하지 않는다.
- 전처리 후 키 중복, 타깃 양성률, 연도·차수별 표본, 특성별 결측률을 보고한다.

## 8. 재현 실행

```powershell
uv sync --group ai --group dev
uv run python -m src.ml.preprocessing.run_official
uv run pytest -q tests/ml/test_preprocessing.py
```

`requirements-ml.txt`은 UV를 사용할 수 없는 환경을 위한 최소 의존성 목록이다. 프로젝트의 공식 실행환경은 Python 3.13과 `uv.lock`을 기준으로 한다.

집계 산출물은 전처리 버전별 재현 결과다. 모델 브랜치에서 라벨 또는 적격 조건을 변경하면 표본 수가 달라질 수 있으므로 모델 카드에 전처리 버전과 Git 커밋을 기록하고, 다른 버전의 집계값을 혼용하지 않는다.
