# 9/10 실제 API 연동 검증 결과 · 수인 프론트

## 결론

8023의 회원가입 → 건강정보 저장 → 분석 요청 → 챌린지 선택 → 일일 기록 → 재로그인 복원은 실제 HTTP와 독립 SQLite DB로 확인했다. 다만 **실제 모델·Worker·XAI·CV·제조사 워치·개인 숲 보상까지 통합 완료된 환경은 아니다.**

- 대상: `http://127.0.0.1:8023`, `AH_05_02-local-latest-20260910`.
- `/api/health`: `status=ok`, `database=ok`, `redis=embedded-demo`.
- 검증은 `?preview=...`가 아닌 실제 회원가입·로그인 경로에서 수행했다.
- 브라우저 네트워크 응답을 모킹하거나 프론트 상태를 성공으로 강제 변경하지 않았다.
- 최종 실행: 30개 검사 중 28개 통과, 2개 실패. **데모/미구현 상태를 올바르게 반환하는 검사도 통과에 포함되므로, 기능 28개가 운영 완료됐다는 뜻은 아니다.**
- 백엔드·Worker·프론트 제품 코드는 이번 검증에서 수정하지 않았다. 테스트와 이 문서만 추가했다. 기존 UI 변경은 보존했다.

## 확인된 연동 누락과 담당자 전달사항

### 1. 지난 4주·전체 리포트: 실제 오류

- `GET /api/v1/reports?period=four-week` → **404 Not Found**.
- `GET /api/v1/reports?period=all` → **404 Not Found**.
- 프론트는 해당 주소를 호출하지만 현재 서버 라우터에는 없다.
- 화면에서 `불러오기 실패`와 `다시 불러오기`가 표시되고, 재시도해도 동일한 404가 발생하는 것을 확인했다.
- API 담당자와 경로·응답 계약을 확인해야 한다. 서버 구현 또는 승인된 대체 경로가 필요하며, 프론트에서 예시 데이터로 성공처럼 대체하지 않는다.
- 프론트 참조: `src/frontend/app.js`의 `loadReportPeriod`, `loadMoreReportCycles`.

### 2. 모델·Worker: 원본 파일 및 실행 환경 필요

- 현재 선별 v0.6.1 / 미래 RF25 v1.1 SAV의 결과 응답을 조회했지만 모두 데모 처리였다.
- 두 응답 모두 `display_allowed=false`, `operational_model_activated=false`.
- `app/services/ai_jobs.py`는 `DEMO_MODE`일 때 `_complete_demo_prediction` / `_complete_demo_current_screening`을 호출한다.
- 현재 작업 폴더에 `models/artifacts` 디렉터리가 없다. 필요한 원본 체크섬과 설치 절차는 `docs/LOCAL_LATEST_20260910.md` 참고.
- 모델 담당자에게 원본 및 실행 환경을 받은 뒤, 별도 실제 추론 환경에서 Redis → Worker → 결과 저장을 검증해야 한다. 현재 8023을 임의로 실모델 모드로 전환하지 않았다.

### 3. XAI: 준혁님 전달 필요

- 두 모델의 `/predictions/{id}/risk-factors` 모두 `status=not_available`, `items=[]`, `shap_claimed=false`.
- 현재 라우터는 빈 설명 목록을 반환하므로 개인별 영향 요인 3~5개 표시는 검증할 수 없다.
- 오늘/미래 각각의 설명 결과, 표시 승인 조건, 영향 방향·변경 가능 여부 필드 계약이 필요하다.

### 4. CV: 준혁님 전달 필요

- 현재 `/food-analyses`는 `image_name`만 받아 이름의 키워드로 분류한다.
- 사용자 확인 저장 API는 동작하지만 실제 CV 추론 연동 완료로 간주할 수 없다.
- 실제 이미지 업로드·분석 상태·신뢰도·무관/중복 이미지·재촬영/대체 인증 계약이 필요하다.
- 챌린지 사진 인증 API의 실제 업로드·모델 판정은 이번 검사 범위에 포함하지 않았다.

### 5. 웨어러블·교육: 빛샘님 전달 필요

- 수동 요약 저장과 출처 기반 교육 응답은 동작한다.
- 제조사 인증·Apple 원본 데이터 정제 파이프라인까지의 검증은 아니다.
- 제조사별 입력 예시, 연결 실패 및 재연결 정책, 자동 인증 대상 챌린지 매핑을 확인해야 한다.
- 퀴즈 정답·해설·진도 저장 UI 전체 검증은 추가로 필요하다.

### 6. 실제 보상 → 개인 숲: 세준님과 계약 확인

- 개인 진입 함수 `enterPersonalForest()`는 `/forest?demo=1`로 이동한다.
- 지갑·인벤토리 조회 API는 200이지만, 간편 기록 1개 전후 `/wallet` 잔액은 모두 0이었다.
- **일부 기록만 수행한 결과이므로 잔액 0을 보상 버그라고 단정하지 않는다.** 기존 일일 보상 코드는 선택 챌린지 완료 조건과 별도 수령 절차를 갖는다.
- 오늘 확정할 보상 조건과 실제 개인 숲 세션·잔액 저장 경로를 맞춘 뒤, 전체 완료 → 수령 → 중복 수령 방지 → 숲 반영 → 재로그인 복원을 별도로 검증해야 한다.

## 추가 검증이 필요한 항목

- 실제 Worker 지연·시간초과·한 모델만 실패·실패 모델만 재시도.
- 동의 철회 후 서버 쓰기 차단 및 재동의 복원.
- 두 실제 테스트 계정의 초대 수락·공동 숲 권한·다른 기기 복원.
- CV 이미지 업로드의 정상·낮은 신뢰도·무관·중복 사례.
- 확정 보상 계약에 따른 전체 완료·수령·중복 방지.
- 모바일에서의 실제 API 연결 흐름과 접근성 오류 초점 점검.
