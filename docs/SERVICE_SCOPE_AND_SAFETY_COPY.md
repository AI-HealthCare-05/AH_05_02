# 서비스 대상·제외 범위 및 의료 안전 문구

| 항목 | 내용 |
|---|---|
| 문서 버전 | v1.0 |
| 작성일 | 2026-08-19 |
| 작성 책임 | 정세준(PM·기획·문서·QA) |
| 상태 | Sprint 2 구현 기준선 |
| 관련 문서 | `REQUIREMENTS.md` v2.0, `API_SPEC.md` v2.0 |

> 이 문서는 프로젝트의 기획·구현 기준이며 법률 자문이나 의료 지침이 아니다. 외부 공개·상용화 전에는 실제 사용목적과 표시·광고 문구를 기준으로 식품의약품안전처 및 개인정보 전문가의 검토를 받는다.

## 1. 확정 원칙

- 서비스 목적은 **당뇨병 진단·처방이 아니라 미래 발병 위험 선별과 건강교육**이다.
- 서비스 이용 가능 연령, 핵심 타깃, 모델 적용 가능 연령을 서로 구분한다.
- 당뇨병 기진단자는 미래 발병 예측과 개인화 추천 대상에서 제외한다.
- 고위험 또는 경고 증상이 있는 사용자는 챌린지보다 검사·의료기관 안내를 먼저 확인한다.
- 약물의 시작·중단·용량 변경과 치료 효과를 서비스가 권고하거나 보장하지 않는다.
- 사용자 화면에는 원시 예측확률보다 검증된 임계값에 따른 `낮음·주의·높음` 범주를 우선 표시한다.

## 2. 이용자 범위

### 2-1. 세 가지 판정값

| 판정 | 의미 | 구현 기준 |
|---|---|---|
| `service_eligible` | 계정·공개 건강교육 등 서비스 이용 가능 여부 | 만 19세 이상 및 필수 약관 동의 |
| `target_segment` | 서비스가 우선 해결하려는 사용자 집단 | 만 40세 이상 당뇨병 미진단자 |
| `model_eligible` | 현재 활성 모델로 개인화 예측을 실행해도 되는지 | 모델 카드의 연령·모집단·필수 입력·제외 조건 충족 |

> KLoSA 최초 표본은 2006년 당시 만 45세 이상이다. 따라서 KLoSA만으로 학습·검증한 모델은 별도 근거 없이 40~44세에게 적용하지 않는다. `40세 이상`은 서비스의 핵심 타깃이며, 실제 예측 연령은 활성 모델 카드의 `min_age`·`max_age`로 통제한다.

### 2-2. 대상·제외 매트릭스

| 사용자 상태 | 일반 정보·계정 | 개인화 예측 | 개인화 챌린지 | 다음 행동 |
|---|---:|---:|---:|---|
| 만 19세 미만 | 공개 정보만 | 차단 | 차단 | 성인 대상 서비스임을 안내 |
| 만 19~39세 미진단 | 가능 | 활성 모델이 해당 연령을 검증한 경우만 | 예측과 무관한 일반 챌린지만 | 모델 적용 범위 안내 |
| 만 40~44세 미진단 | 가능·핵심 타깃 | 활성 모델 `min_age`가 40 이하일 때만 | 일반 챌린지 가능 | KLoSA 단독 모델이면 예측 차단 |
| 만 45세 이상 미진단 | 가능·핵심 타깃 | 동의·입력·모델 조건 충족 시 가능 | 가능 | 건강정보 입력·예측 |
| 당뇨병 기진단 | 가능 | 차단 | 개인화 추천 차단, 공개 일반 정보만 | 담당 의료진 지침 우선 안내 |
| 응급·경고 증상 응답 | 가능 | 차단 | 차단 | 즉시 의료기관·응급 안내 |
| 건강정보 처리 미동의 | 계정 기능만 | 차단 | 개인화 기능 차단 | 동의 목적·항목 안내 |
| 필수 입력 누락·범위 오류 | 가능 | 입력 수정 전 차단 | 예측 기반 추천 차단 | 누락 항목·단위·수정법 안내 |
| 활성 모델 검증 모집단 외 | 가능 | 차단 | 예측과 무관한 일반 챌린지만 | 모델 적용 범위 안내 |

임신 등 특정 모집단의 제외 여부는 임의로 고정하지 않고 활성 모델 카드의 검증 범위에 따른다. 해당 모집단에서 검증되지 않은 모델은 `MODEL_POPULATION_OUT_OF_SCOPE`로 예측을 차단한다.

## 3. 판정 사유 코드

| 코드 | 조건 | 사용자 다음 행동 |
|---|---|---|
| `UNDER_MINIMUM_SERVICE_AGE` | 만 19세 미만 | 공개 정보로 이동 |
| `CONSENT_REQUIRED` | 건강정보 처리 동의 없음·철회 | 동의 안내 또는 개인화 기능 종료 |
| `DIAGNOSED_DIABETES` | 당뇨병 기진단 응답 | 예측 중단, 의료진 지침 안내 |
| `URGENT_MEDICAL_ATTENTION` | 사전에 검토된 경고 증상 응답 | 의료기관·119 안내 |
| `MODEL_AGE_OUT_OF_RANGE` | 활성 모델 검증 연령 밖 | 일반 정보·일반 챌린지 안내 |
| `MODEL_POPULATION_OUT_OF_SCOPE` | 활성 모델이 검증하지 않은 모집단 | 일반 정보·의료진 상담 안내 |
| `MISSING_REQUIRED_INPUT` | 필수 입력 누락·오류 | 입력 화면으로 복귀 |

API는 판정 결과와 함께 하나 이상의 `reason_codes`와 하나의 `next_action`을 반환한다. 화면은 코드명을 그대로 노출하지 않고 아래의 검토 문구로 변환한다.

## 5. 금지 표현과 대체 표현

| 사용하지 않는 표현 | 사용하는 표현 |
|---|---|
| 당뇨병입니다 / 당뇨병이 아닙니다 | 미래 발병 위험이 `낮음·주의·높음` 범주로 분류되었습니다 |
| 발병 확률 80%입니다 | 검증된 임계값 기준 위험 범주는 `높음`입니다 |
| 정상·안전합니다 | 현재 모델 기준 `낮음`이며, 위험이 없다는 뜻은 아닙니다 |
| 4주 후 위험이 10% 감소했습니다 | 4주간 챌린지 수행률과 건강정보 입력 변화를 보여드립니다 |
| 이 챌린지로 당뇨병을 치료·예방합니다 | 건강한 생활습관 형성을 돕는 일반 건강 실천입니다 |
| 약을 끊으세요 / 용량을 늘리세요 | 복약 변경은 담당 의료진과 상담하세요 |
| 병원에 갈 필요가 없습니다 | 우려되는 증상이나 검사 결과가 있으면 의료기관에서 확인하세요 |

사용자 화면에는 모델의 원시 확률을 건강 개선율·치료 효과·개인별 확정 발병률처럼 표시하지 않는다. 원시 확률은 모델 평가와 감사가 필요한 내부 정보로만 저장한다.

## 6. API·DB 구현 기준

### 6-1. 적합성 응답 최소 필드

```json
{
  "service_eligible": true,
  "target_segment": "primary_40_plus",
  "model_eligible": false,
  "reason_codes": ["MODEL_AGE_OUT_OF_RANGE"],
  "next_action": "general_health_information",
  "active_model": {
    "model_key": "diabetes_incidence",
    "version": "v1.0.0",
    "min_age": 45,
    "max_age": null
  }
}
```

- 정책상 차단된 예측 작업 생성은 `403`, 필수 입력 형식·범위 오류는 `422`를 사용한다.
- `EligibilityCheck`에는 판정 당시 모델 버전·판정 결과·사유 코드·다음 행동·문구 버전을 저장한다.
- `Prediction`에는 모델 버전·결과 범주·내부 확률·예측 시각·대상 모집단 버전을 저장한다.
- 공개 결과 API는 `risk_category`, `model_version`, `model_population`, `predicted_at`, `disclaimer`를 반환한다.
- 모델 카드에는 최소한 `min_age`, `max_age`, 학습 모집단, 제외 모집단, 결과 정의, 관측 기간, 임계값 버전을 기록한다.

### 6-2. 상태 코드

| 상황 | 코드 | 예시 오류 코드 |
|---|---:|---|
| 적합성 판정 자체는 정상 완료 | `200` | 응답의 `reason_codes`로 설명 |
| 기진단·미동의·모델 범위 외 예측 요청 | `403` | `PREDICTION_NOT_ALLOWED` |
| 필수 입력 누락·형식·단위 오류 | `422` | `MODEL_INPUT_INVALID` |
| 활성 모델 없음·준비 안 됨 | `503` | `MODEL_UNAVAILABLE` |

### 7-1. 건강정보 철회·탈퇴 처리 기준

- 동의 철회 즉시 신규 건강정보 수집, 개인화 예측, 개인화 추천을 중지한다.
- 철회 이력은 동의 준수 증빙을 위해 일반 서비스 데이터와 분리하고 접근을 제한한다.
- 회원 탈퇴 시 법적 보존 의무가 없는 식별 가능한 건강정보는 삭제 대기 상태로 전환한다.
- 프로젝트 운영 기준은 탈퇴 후 30일 이내 삭제 또는 복구 불가능한 익명화 완료이며, 처리 시각·처리 방식·정책 버전만 감사로그에 남긴다.
- 익명화된 통계는 개인을 재식별할 수 없어야 하며, 원본과 연결되는 키를 보존하지 않는다.
- 위 기간은 프로젝트의 개인정보 최소화 정책이며 법정 보존기간을 의미하지 않는다. 실제 배포 전 처리 목적과 관련 법령에 대한 별도 검토를 받는다.

### 7-2. 위험 범주 승인 기준

- `낮음·주의·높음`의 숫자 임계값은 PM이 임의로 정하지 않는다.
- 검증 세트에서 AUROC·AUPRC·민감도·특이도·Brier·Calibration을 확인하고, 고위험 누락 비용을 고려해 후보 임계값을 정한다.
- 승인된 임계값에는 `threshold_version`, 대상 모집단, 모델 버전, 평가일을 기록한다.
- 승인 전에는 축소 표본 점수를 개인 발병확률이나 운영 위험 범주로 노출하지 않는다.
