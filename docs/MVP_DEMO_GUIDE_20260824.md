# 간당간당 전체 기능 MVP 실행 가이드

## 실행

저장소 루트에서 다음 명령을 실행한다.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run_mvp_demo.ps1
```

브라우저에서 다음 주소를 연다.

- 서비스: `http://127.0.0.1:8000/`
- API 문서: `http://127.0.0.1:8000/api/docs`
- 상태 확인: `http://127.0.0.1:8000/api/v1/ready`

`DEMO_MODE`는 Docker 없이 사용자 흐름을 확인하기 위한 로컬 전용 실행 방식이다. SQLite 파일은 `storage/gandang_mvp.sqlite3`에 생성되며 `.gitignore` 규칙에 따라 Git에 포함되지 않는다.

## 확인할 사용자 흐름

1. 서비스 안내
2. 신규 가입·건강정보 동의 또는 기존 계정 로그인
3. 연령·기진단·경고 증상 적합성 확인
4. 건강·생활습관 정보 입력
5. 비동기 예측 작업 계약과 개발용 안전 결과 확인
6. 검증된 설명 상태와 피드백
7. 일반 건강 챌린지 선택
8. 일일 기록·주간 리포트·건강교육·가족·친구·웨어러블·RAG·CV·OCR·알림·PDF

## 데모 모드 안전 경계

- SQLite와 인프로세스 Worker는 `DEMO_MODE=true`일 때만 사용한다.
- 개발 provider는 확률·점수·위험 범주를 만들지 않는다.
- 결과는 진단·처방이 아니라 시스템 연결과 건강교육 흐름 확인용이다.
- 식단 분류와 OCR은 `development_mock`이며 사용자 확인 전 건강기록에 반영하지 않는다.
- RAG는 승인된 문서에 일치하는 근거가 있을 때만 답하고 원문 링크를 표시한다.
- 가족·친구에게 건강정보와 예측 결과를 공유하지 않는다.

## 검증 결과

- 가입 → 동의 → 적합성 → 건강정보 → 예측 작업 → 결과 → 챌린지 → 대시보드 완료
- 기존 사용자 로그인 후 진행 중 대시보드 복귀 완료
- 일일 챌린지 기록과 주간 요약 갱신 완료
- 웨어러블 일일 요약 가져오기 완료
- RAG 근거 답변과 복약 변경 질문 거절 완료
- 식단 분류·OCR 초안과 사용자 확인 완료
- 가족·친구 초대·수락·공동 챌린지 생성 완료
- 웹 알림 설정 완료
- PDF 응답 계약과 파일 헤더 테스트 완료
- 브라우저 오류·경고 로그 없음

## 운영 모드와의 차이

운영·통합 환경은 기존대로 MySQL, Redis Stream, 별도 AI Worker, Nginx를 사용한다. `DEMO_MODE=false`가 기본값이므로 로컬 데모 경로가 운영 구조를 자동으로 대체하지 않는다.
