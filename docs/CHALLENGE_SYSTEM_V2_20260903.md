# 생활습관 챌린지 구체화 명세 v2.1
작성일: 2026-09-03 | 상태: 구현 인계용 설계안(임상 검증·운영 승인 완료를 의미하지 않음)

## 1. 목적과 변경 범위
기존의 “규칙적인 식사 체크”, “물 마시기”, “활동 확인”을 행동·횟수·완료 조건이 있는 챌린지로 구체화한다.
주 대상은 미진단·위험군 사용자이며, 고령자 접근성을 반영한다. 기존 기진단·긴급증상·의료기관 안내 우선 정책을 약화하지 않는다.
이 문서는 현재 코드 변경 완료 보고가 아니다. 실제 구현은 별도 ‘| 웹서비스 구현’ 작업에서 수행한다.

- 기본 하루 3개 슬롯: 쉬움(E)·보통(M)·도전(H) 각 1개.
- 사용자 추가 확정: 기본 하루 3개는 T1·T2·T3도 반드시 각 1개. 각 유형의 난이도는 고정하지 않는다. 안전·접근성 예외는 사유와 대체 내역을 명시한다.
- 인증 유형(T1/T2/T3)은 난이도와 독립적이다. T1=어려움으로 고정하지 않는다.
- 분야: 식단(diet), 운동(activity), 생활관리(routine; 음료·수분·수면).
- 선호 모드: 식단 중심(diet_focus), 운동 중심(activity_focus), 균형(balanced).
- 9개 행동군 × 3개 난이도 = 기본 27개 템플릿. 사진 접근성 대체 카드는 별도 코드로 관리.
- 구체 횟수, 분량, 3개 슬롯, 보상 규칙은 앱 운영을 위한 설계 수치다. 논문이 이 앱 조합의 효과를 검증한 것은 아니다.

## 3. 인증 유형
| 유형 | 사용자 행동 | 시스템 확인 범위 | 완료 조건·표시 |
|---|---|---|---|
| T1 인증+사진 검증 | 식사·영양표시 사진 제출 | 명시된 시각 조건 또는 라벨 수치와 입력의 일치 확인 | 필요한 회차별 검토 통과 후 ‘사진 조건 확인’ |
| T2 인증 제출 | 식사 사진 또는 활동기록·타이머 화면 제출, 필요한 시각·횟수 직접 입력 | 파일 유효성·필수 기록 확인만. 건강 적절성·실제 수행 진위 판단 안 함 | 제출 조건과 자기보고 목표 충족 시 ‘기록 제출 완료’ |
| T3 체크 | 회차별 수행 체크, 필요 시 분·mL 등 직접 입력 | 형식·중복·목표 횟수 확인 | 목표 회차 충족 시 ‘자가 기록 완료’ |

공통:
- T1도 “실제 먹었다”, “혈당이 개선됐다”, “칼로리가 정확하다”를 검증하지 못한다.
- T2는 EXIF·GPS·사진 진위 확인을 요구하지 않는다. 업로드 시각은 행동 시각의 증명이 아니다.
- T3의 수분량 입력은 자가 기록이며 사진 인증이 아니다.
- T1은 검증 대기/판단 어려움/재제출과 통과를 구분한다. AI 오류·타임아웃을 통과로 바꾸지 않는다.
- 판정 확신이 없으면 재촬영/사용자 정정/담당자 검토 또는 별도 T3 대체 카드로 전환한다.
- 사진을 사용할 수 없는 사용자에게 사전 정의한 체크형 대체 카드를 제공하고 점수·기본 보상에서 차별하지 않는다.
- 사진 검증 엔진이 없으면 T1 운영 추천을 비활성화하거나 실제 수동 검토 대기만 제공한다. 가짜 검증으로 완료 처리 금지.

## 4. 난이도와 일일 배정
E 쉬움: 한 번의 작은 행동 또는 짧은 기록.
M 보통: 같은 행동을 두 번 반복하거나 한 단계 더 구체적인 구성.
H 도전: 세 번 반복하거나 계획·기록을 함께 수행. 고강도·과음수·절식의 의미가 아님.

### 모드별 기본 배정
| 모드 | 분야 비율 | 쉬움 예시 | 보통 예시 | 도전 예시 |
|---|---|---|---|---|
| 식단 중심 | 식단 2 + 생활관리 1 | D03-E 한 끼 기록(T2) | H01-M 평소 당 음료 2회 대체(T3) | D01-H 두 끼 구성(T1) |
| 운동 중심 | 운동 2 + 식단 1 | D01-E 한 끼 채소 구성(T1) | A01-M 걷기 5분×2회(T2) | A02-H 좌식중단 2분×3회(T3) |
| 균형 | 식단 1 + 운동 1 + 생활관리 1 | H01-E 평소 당 음료 1회 대체(T3) | D01-M 한 끼 구성(T1) | A01-H 걷기 5분×3회(T2) |

당뇨 관련성에 따른 우선 후보는 D01 식사 구성, A01 식후 걷기, A02 좌식중단, H01 당 음료 대체다. D02 영양표시·D03 식사 기록은 교육·실천 지원, H02 수분 기록·R01 수면 준비는 보조 생활관리다. A03은 안전 확인 전 비활성이다. 이 우선순위는 제품 설계이며 효과 크기의 의학적 순위가 아니다.
H01은 평소 섭취 기회와 제한 확인이 충족될 때만 배정하며, 불가하면 같은 난이도·T3인 H02로 대체한다. 수분 기록 자체를 당뇨 예방 효과로 표현하지 않는다.
운동 중심도 T1을 채우려고 운동 사진으로 운동량을 검증하지 않는다. 식단 T1 1개 + 운동 T2/T3로 구성한다.

배정 규칙:
1. 안전 제한·적격성 → 가능한 행동/촬영 접근성 → T1/T2/T3 각 1개와 E/M/H 각 1개를 동시에 충족하는 서로 다른 행동군 조합 → 모드와 당뇨 관련 우선순위 순으로 선택한다. 단순 상위 3개 추출은 금지한다.
2. 같은 행동군의 E/M/H를 하루에 중복 배정하지 않는다. 걷기·좌식중단은 동일 시간 구간을 이중 적립하지 않는다.
3. 일반 적격 조건에서 T1/T2/T3는 정확히 각 1개다. 하루 T1 필수 사진은 최대 2장으로 설계한다. 실제 사진 검토가 불가능하면 가짜 검증으로 개수를 맞추지 않고, 접근성/검증 불가 대체와 proof_mix_exception_reason을 표시한다.
4. 성능 점수·위험도가 높다고 난이도를 자동 상승시키지 않는다. 최근 수행·통증·선호·촬영 가능성을 별도로 확인한다.
5. 세 난이도는 기본 구성이지 강제 의무가 아니다. 안전상 H가 불가하면 낮은 난이도/기록형 카드로 교체하고 사유를 표시한다.
6. 충분한 적격 후보가 없으면 안전한 적은 수만 제공하며, 3개를 맞추기 위해 금기 행동을 넣지 않는다.
7. 비가 오는 날 야외 걷기는 실내 걷기로 대체할 수 있으나, 균형·보행 제한이 있으면 별도 안전한 기록형 대안을 제공한다.
8. 새로고침으로 목표가 바뀌지 않도록 서버에서 사용자·KST 날짜·정책 버전별 일일 계획을 한 번 생성한다.
9. 사용자가 수동 변경할 때도 서버가 제한·중복을 재검사한다. 식단형의 보완 슬롯은 주간 계획에서 운동과 생활관리를 순환한다.

## 5. 챌린지 카탈로그(27개)
공통 횟수는 해당 카드가 배정된 날의 목표다. 주간 빈도는 상한/추천 일정이며, 매일 모든 카드를 수행하는 것이 아니다.
아래 숫자는 제품의 시작용 설계안이며 개별 운동·영양 처방이 아니다.

### 식단
| 행동군·유형 | 쉬움 E | 보통 M | 도전 H | 완료 기준·주간 배정 |
|---|---|---|---|---|
| D01 식사 구성 / T1 | 예정된 한 끼에 비전분 채소 1종 포함해 사진 1장 | 예정된 한 끼에 채소·단백질·탄수화물 식품 포함해 사진 1장 | 예정된 두 끼에 M 구성 적용, 각 1장(총 2회) | 보이는 구성 조건 확인. 하루 목표 1/1/2끼, 주 3~5일 후보. 섭취량·접시 면적 비율을 자동 확정하지 않음 |
| D02 영양표시 읽기 / T1 | 라벨 1개의 표시 기준량·당류 값을 사진과 함께 입력 | 같은 종류 제품 라벨 2개의 기준량·당류·총탄수화물 입력 | M에 더해 같은 기준량(100g 또는 100mL)으로 비교 결과 작성 | E는 라벨 1개, M/H는 2개. 계산·입력과 라벨 일치 확인, 주 1~2일. 구매 불필요. 0g도 정상 입력 |
| D03 식사 시간·내용 기록 / T2 | 예정된 식사 1회의 시각·내용과 사진 제출 | 예정된 식사 2회 기록·사진 제출 | 예정된 식사 최대 3회 기록·사진과 다음날 개선점 1줄 | 식사 1/2/3회 기록. 주 3~5일 후보. 계획된 끼니보다 많은 목표는 배정하지 않음. 정확한 시각 준수·끼니 추가 강요 없음 |

D01 예시: 채소=오이·시금치·브로콜리 등, 단백질 식품=두부·달걀·생선 등, 탄수화물 식품=밥·감자 등. 알레르기·치료식·저작/연하 제한이 우선이며 특정 식품 구매를 강제하지 않는다. 국·찌개·혼합요리는 사용자가 재료를 설명할 수 있고 판단 곤란은 실패로 단정하지 않는다.
D02는 영양정보 이해 교육이며 당류가 낮다는 이유만으로 ‘건강한 제품’ 인증을 하지 않는다. 국내 라벨에는 첨가당 표시가 없을 수 있어 필수값으로 요구하지 않는다. 고형·액상 기준을 혼합 비교하지 않는다.
근거: S1/S4/S8. D03의 기록 횟수는 운영 설계이며 끼니 수와 질병위험을 직접 연결하지 않는다.

### 운동
| 행동군·유형 | 쉬움 E | 보통 M | 도전 H | 완료 기준·주간 배정 |
|---|---|---|---|---|
| A01 식후 편안한 걷기 / T2 | 5분×1회 | 5분×2회(총 10분) | 5분×3회(총 15분) | 가능한 식후 편한 시간에 수행. 각 회차 시간 자가 기록 + 하루 활동기록/타이머 화면 1장. 주 3~5일 시작 후보 |
| A02 오래 앉기 중단 / T3 | 2분 움직이기×1회 | 2분×2회 | 2분×3회 | 오래 앉았던 서로 다른 구간에서 수행·체크. 같은 회차 중복 금지. 주 5~7일 후보 |
| A03 의자에서 일어나기 / T3·조건부 | 5회×1세트 | 8회×1세트 | 8회×2세트(사이 1~2분 쉬기) | 안정된 의자, 안전하게 독립 수행 가능·운동제한 없음 확인 후 배정. 주 2일, 연속일 제외. 세트별 완료 기록 |

A01 촬영 불가 시 동일 목표의 A01-*-C 체크형 대안. 사진은 걷기 진위를 증명하지 않으며 완료는 자기보고에 기반한다.
A02의 “오래 앉기” 안내는 개인 일정에서 30~60분 정도 앉은 구간을 확인하는 시작용 예시다. 정확한 시간마다 움직여야 치료 효과가 생긴다고 주장하지 않는다. 앱의 하루 1~3회는 앉기 중단 전체 필요량을 뜻하지 않는다.
A03은 기본 배정에서 제외하고 사전 안전 검토·안내 승인 후 활성화한다. 낙상·통증·최근 수술·운동 제한·안전 수행 미확인이면 추천하지 않는다. 숨참기·최대 반복 경쟁을 요구하지 않는다.
운동 공통: 흉통, 심한 호흡곤란, 실신감, 어지럼, 통증 시 중단하고 적절한 의료 도움을 안내한다. 한발 서기·계단 달리기·고강도 운동은 초기 목록에 넣지 않는다.
근거: S2/S3/S5/S9. 해당 반복·분 단위 목표는 앱 적응 단계이며 연구 효과나 주간 권고 달성을 보장하지 않는다.

### 생활관리: 음료·수분·수면
| 행동군·유형 | 쉬움 E | 보통 M | 도전 H | 완료 기준·주간 배정 |
|---|---|---|---|---|
| H01 당 음료 대신 무가당 음료 / T3 | 평소 당 음료를 마실 기회 1회 대체 | 2회 대체 | 3회 대체 | 물 또는 개인에게 적합한 무가당 음료로 바꾼 회차 체크. 평소 당 음료 빈도가 목표 이상일 때만 배정. 주 3~5일 후보 |
| H02 수분 섭취 돌아보기 / T3 | 오전 1회, 지금까지 마신 양 기록 | 오전·오후 2회 구간별 기록 | 오전·오후·저녁 3회 구간별 기록 | 각 구간 실제 섭취량(mL 또는 개인 컵 용량×잔 수)을 기록. 0mL도 유효. 주 5~7일 후보. 물 추가 섭취는 완료 조건 아님 |
| R01 잠들기 전 준비 / T3 | 예정 취침 전 10분 밝은 화면을 줄이고 조용한 활동 | 20분 | 30분 | 취침 전 행동 1회 자가 체크. 주 3~5일 후보. 실제 수면시간·숙면 여부는 보상 조건 아님 |

H01: 원래 당 음료를 마시지 않으면 미배정한다. 기회를 만들기 위해 음료를 더 마시게 하지 않는다. 수분 제한·연하 제한·치료식 확인이 안 되면 대체 카드로 전환한다.
H02: 모든 사용자에게 물 2L/8잔 목표를 주지 않는다. 예시 컵 용량은 입력 편의를 위한 값이며 개인 목표가 아니다. 구간별 양을 더하되 누적량을 반복 합산하지 않는다. 질환·날씨·체격을 이유로 앱이 임의 증량하지 않는다. 수분 제한이 있는 경우에도 단순 기록은 가능하나 의료진이 정한 계획이 우선이다.
근거: S4/S6/S7. 생활관리 카드는 당뇨 치료·혈당 개선 검증 기능이 아니다.

## 6. 반복·진행·4주 운영
- 예: A01-M = 5분 이상 회차 2개. 10분 연속 기록 1개로 자동 치환하지 않으며, 처음부터 연속 목표로 바꾸려면 다른 템플릿/버전을 쓴다.
- 각 카드에 ‘회차 1/2’와 ‘총 5/10분’을 함께 표시한다.
- 1주차: 접근성·가능 시간·제한 확인, 안전한 시작 목표 선택.
- 2주차: 선택한 목표 유지와 기록 습관. 자동 증량 없음.
- 3주차: 사용자 요청과 불편 증상 없음 확인 후 한 단계 조정 가능.
- 4주차: 수행·제출·확인 비율과 지속 가능성 요약. 체중·혈당·발병위험 개선율로 변환하지 않음.
- 주간 권고량과 앱 수행량은 별개로 표시한다. 15분×5일 달성은 중강도 150분 권고 충족이 아님.
- 질병 고위험, 기진단 전환, 긴급 증상이 있으면 기존 서비스의 안내·중단 정책을 우선 적용한다.
- 휴식·안전상 건너뛰기 가능. 건강하지 않음/실패자로 낙인찍는 문구나 과도한 연속 수행 패널티 금지.

## 7. 완료·검토·보상 규칙
- 진행 상태: assigned → in_progress → submitted(T1) → completed. 검증 상태와 진행 상태는 별개 필드.
- verification_status: not_required / pending / passed / needs_retry / inconclusive.
- T1 완료 = 목표 회차 수행 자기보고 + 해당 시각 조건 검증 통과. 검증 대기 중 완료·보상을 선지급하지 않음.
- T2 완료 = 목표 회차 기록 + 유효 인증파일 제출. status는 not_required, ‘AI 검증 완료’ 표시 금지.
- T3 완료 = 목표 회차 체크. status는 not_required.
- 일일 회차 상한, 사용자/배정일/슬롯/회차의 유일성, 서버 측 완료 집계를 둔다. 클라이언트 is_completed만 신뢰하지 않는다.
- 배정일은 Asia/Seoul 기준. 로그 날짜를 UTC 날짜로 덮어쓰지 않는다.
- 제출은 배정일 종료까지, 이미 접수한 T1은 다음날 검토되어도 원래 날짜의 보상으로 귀속. 검토 대기는 사용자 실패로 표시하지 않는다.
- 동일 사진의 기술적 중복은 재시도로 멱등 처리하며 두 슬롯 보상에 중복 사용하지 않는다. 다른 날 식단이 비슷하다는 이유만으로 부정행위로 판정하지 않는다.
- 보상은 기존 당근/보물상자 경제를 재사용한다. 물의 양·운동량·체중감량·촬영 여부로 추가 보상하지 않는다.
- 서버에서 reward_source_id 고유값 + 트랜잭션으로 하루 보물상자 중복 지급 방지. 늦은 검토에도 한 번만 지급.
- 유효한 배정 3개가 모두 완료되면 일일 보물상자. 안전상 더 적게 배정한 날도 확정된 활성 슬롯 전체 완료로 계산하고, 미배정 날에는 보상하지 않는다.
- 단순 건너뛰기로 보상 요건을 줄이지 않는다. 안전 대체는 서버가 새 슬롯을 확정하고 기존 슬롯 보상은 유지/중복하지 않는다.
- 기존 진행 중 주기는 소급 변경하지 않는다. 다음 날부터 새 일일 계획을 적용하거나 사용자 동의 후 전환. 완료 이력과 기존 보상은 보존한다.

## 8. 화면 변경
카드마다 분야, 난이도, 인증 유형, 구체 목표, 진행률, 안전 안내, 근거 링크를 보여준다.

예시:
[운동] [보통] [기록 제출]
식후 편안하게 5분씩 두 번 걷기
오늘 목표: 5분 × 2회 / 현재 1회 완료
버튼: 회차 기록 · 인증 올리기 · 다른 챌린지로 바꾸기 · 근거 보기

- T1 버튼: 사진 올리기 → 검토 중/사진 조건 확인/다시 올리기.
- T2 버튼: 기록·인증 올리기 → 기록 제출 완료.
- T3 버튼: 이번 회차 체크 → 목표 충족 시 자가 기록 완료.
- 카메라 접근 거부·업로드 실패·검증 지연·네트워크 재시도 UI 필요.
- 식단/운동/균형 선택과 난이도 조절·접근성 대체를 제공.
- ‘사진이 검증되었으므로 실제 섭취 확인’ 문구 금지.
- 기존 게임의 일일 퀘스트는 같은 서버 일일 계획을 사용하며 별도의 하드코딩 목록을 유지하지 않는다.

## 9. 구현 데이터 계약(제안)
실제 필드·경로는 최신 ERD/API와 대응표를 만든 뒤 기존 계약을 보존하며 확장한다.
- ChallengeTemplate: code, version, family_id, domain, subdomain, difficulty, proof_type, title, instructions, daily_goal{unit,target_sessions,per_session_quantity}, weekly_schedule, visual_criteria, exclusion_flags, alternative_code, evidence_refs.
- DailyChallengeAssignment: user_id, cycle_id, assigned_date_kst, slot, template_code/version, goal_snapshot, eligibility_snapshot, status. 일일 정책 버전 저장.
- ChallengeSessionLog: assignment_id, session_index, performed_at, recorded_at, duration/repetitions/intake_amount, user_reported_done.
- ChallengeEvidence: log/assignment 참조, private_object_key, content_hash, mime, submitted_at, deletion_due_at.
- ChallengeVerification: evidence_id, status, criteria_results, reviewer_type/version, reason_codes, reviewed_at. 모델 확신도는 임상 정확도가 아님.
- RewardEvent: assignment/day 참조, unique source key, issued_at.
- 기존 /api/v1 경로, PATCH 부분 수정, router-service-repository 및 ai_worker 구조를 존중.
- 새 인증 API에 인증·소유권 검증 필요. 임의 외부 URL을 서버가 다운로드하지 않음.
- 첨부파일은 jpeg/png/webp, 파일당 10MB 이하를 초기 제안. 확장자와 실제 형식 확인·재인코딩·EXIF 제거·디코딩 크기 제한.
- 사진은 비공개, 짧은 만료의 접근 URL, 로그에 원본/서명 URL 기록 금지. 사진을 Git에 커밋하지 않음.
- 사진 보관은 업로드 후 최대 7일을 초기 정책안으로 제안(법정 기간이라는 뜻 아님). 검토 지연 만료 시 재제출/대체 안내. 파생 썸네일까지 삭제. 실제 배포 전 고지·동의·운영 정책 확인.
- 외부 이미지 AI 전송은 제공자/보관/동의 정책 확인 후 활성화. 사진 속 문자·QR·지시문은 신뢰하지 않고 실행/URL접속하지 않음.
- 운영용 검증 엔진/스토리지 없는 환경은 local demo와 실제 검증을 명확히 구분한다.

## 10. 기존 코드에 대한 인계 포인트
루트에서 읽은 app/services/challenges.py에는 단순 문자열 daily_goal, meal_count_yesterday != 3 추천, 짧은 5개 카탈로그가 있다. 이는 루트 확인 결과이며 실제 작업 브랜치가 더 최신일 수 있다.
- 최신 브랜치에서 다시 점검하고 단순 ‘세 끼 아님 → 불규칙’ 판정을 제거/수정한다.
- 줄 문자열만 바꾸지 말고 회차별 기록·완료·인증 상태와 보상까지 연결한다.
- 기존 max 3개 선택/4주 주기와 새 daily slots를 매핑한다. 기존 로그를 삭제하거나 일괄 재해석하지 않는다.
- 원본 파일의 사용자 변경을 보존하고 app/services/challenges.py, 관련 DTO/모델/마이그레이션/API/프론트/게임/테스트/문서를 함께 갱신한다.
- src/backend에는 신규 기능을 추가하지 않는다.
- 의료 경고·기진단 차단은 프론트뿐 아니라 서버에서도 유지한다.

## 11. 인수 테스트
1. 일반 적격 사용자에게 E/M/H 각 1개와 T1/T2/T3 각 1개, 서로 다른 family 3개가 동시에 재현 가능하게 배정된다.
2. 식단/운동/균형 비율을 만족하고 유형별 난이도가 고정되지 않는다. 예외는 안전/접근성/실제 검증 불가 사유로 추적하고 조용히 T1을 체크로 바꾸지 않는다.
3. 안전 제한/미응답/촬영 제한에 맞는 대체 또는 미배정. 사진 동의 거부로 서비스 전체를 차단하지 않음.
4. A01-M 1회(5분)만으로 완료 불가, 2회 달성 후 유효 기록 제출 시 완료.
5. T1 업로드만으로 완료 불가, 실패·불확실·타임아웃에 가짜 통과 없음.
6. T2는 의료 판정 없이 파일·필수 기록만 확인, T3는 파일 없이 완료 가능.
7. H02 0mL 기록 유효, 더 마셔도 추가 보상 없음, 구간별 양 중복합산 없음.
8. 목표보다 적은 평소 당 음료 빈도에서 H01-M/H 미배정; 기회를 새로 만들지 않음.
9. 늦은 T1 검토·새로고침·중복 클릭·동시 요청·자정 경계에도 원배정일 기준 보상 1회.
10. 다른 사용자 사진/로그 조회 금지, MIME 위장·과대파일·외부 URL 거부, 보관 만료 삭제.
11. 최신 게임 퀘스트·대시보드·API의 목표/완료 수가 일치하고 기존 완료·지갑 이력 유지.
12. 식사/걷기 인증으로 질환 예방 효과나 예측 점수 감소를 생성하지 않음.
13. Ruff/Pytest/프론트 검사, 상태별 UI 및 사진 불가 대체 흐름 확인. 모델 실험·운영 도입은 별개로 보고.
