# FE–BE 추가 연동 과업 (2026-09-08)

## 0. 작업 목적

백엔드에 구현된 동의 철회·당근의 숲·지갑·인벤토리·아바타 기능을 실제 사용자 화면과 연결한다. 브라우저 `localStorage`와 서버 DB에 나뉜 게임 상태를 단일 기준으로 통합해, 새로고침·재로그인·다른 기기에서도 같은 상태가 보이도록 한다.

## 1. 확인된 현황

- 동의 철회 API는 구현되어 있으나 프론트 호출과 설정 화면이 없다.
  - `PATCH /api/v1/consents/{consent_id}/withdraw`
- 최신 통합 브랜치에 지갑·상점·인벤토리·아바타 API가 구현되어 있다.
  - `GET /api/v1/wallet`
  - `GET /api/v1/inventory-items`
  - `GET /api/v1/inventory`
  - `POST /api/v1/inventory/items/{item_id}/purchase`
  - `GET /api/v1/avatar`
  - `PUT /api/v1/avatar/equipment`
- `ApiForestAdapter`가 있으나 기본 실행은 `DemoForestAdapter`와 `localStorage`를 사용한다.
- 숲 슬로건 수정 API는 최신 통합 브랜치에서도 아직 확인되지 않는다.
- 숲 보상·오브젝트 구매의 당근 잔액은 `GameRepository` 지갑을 사용하도록 일부 통합됐지만, `ForestAvatar.carrot_balance`와 `ForestInventory` 같은 중복 구조가 남아 있다.

## 2. 구현 과업

### A. 건강정보 동의 철회

**담당: 이수인(FE), 박빛샘(BE), 정세준(정책·QA)**

- [ ] `개인정보 설정 → 건강정보 수집·이용 동의 → 동의 철회` 화면 및 호출 연결
- [ ] 본인 동의 기록만 철회할 수 있도록 소유권 확인
- [ ] 이미 철회된 요청을 중복 실행해도 안전한 멱등 응답 제공
- [ ] 철회 직후 신규 건강정보·예측·챌린지 사이클 생성을 차단
- [ ] 진행 중인 챌린지 처리 기준 확정 및 적용
- [ ] 일반 페이지·계정 이용은 유지
- [ ] 재동의 시 새 이력 행을 생성하는지 확정
- [ ] 기존 건강정보·예측 결과의 보관·파기 정책과 사용자 안내 확정

**응답 계약 후보**

`consent_id`, `is_agreed`, `withdrawn_at`

### B. 당근의 숲 API 전환

**담당: 이수인(FE), 박빛샘(BE)**

- [ ] 로그인 상태에서는 `ApiForestAdapter`를 사용하도록 전환
- [ ] 카탈로그·숲 조회·오브젝트 배치·제거 API 연결
- [ ] 지갑·상점·인벤토리·구매·아바타 장비 API 연결
- [ ] 슬로건 수정 API와 DTO·응답·권한·길이·금칙어 기준 구현
- [ ] API 실패를 `DemoForestAdapter` 성공으로 자동 대체하지 않고 오류 상태 표시
- [ ] `DemoForestAdapter`는 명시적인 미리보기 모드에서만 허용

### C. 인증·그룹 진입 흐름

**담당: 이수인(FE), 박빛샘(BE)**

- [ ] `로그인 → 그룹 조회 → 기존 그룹 선택 또는 생성 → 숲 진입 → 서버 상태 조회` 흐름 연결
- [ ] 쿠키 또는 토큰 전달 방식을 기존 인증 계약과 통일
- [ ] 현재 그룹 ID 조회·선택 기준 확정
- [ ] 그룹 미가입 사용자의 생성·초대 흐름 제공
- [ ] `401`은 로그인 복귀, `403`은 그룹 권한 안내로 구분

### D. 게임 데이터 단일 책임 확정

**담당: 박빛샘(BE), 정세준(요구사항·QA), 양준혁(보상·모델정보 안전 검토)**

| 데이터 | 단일 관리 위치 |
| --- | --- |
| 당근 잔액·거래 이력 | 게임 API |
| 아이템 카탈로그·보유 수량 | 게임 API |
| 아바타 장착 아이템 | 게임 API |
| 숲 이름·슬로건 | 숲 API |
| 숲 오브젝트 배치 | 숲 API |
| 공동 보상 조건·수령 기록 | 숲 API + 게임 지갑 원장 |
| 구성원별 챌린지 진행률 | 챌린지 API 조회 결과 |

- [ ] `ForestAvatar.carrot_balance` 제거·마이그레이션 또는 레거시 전용 명시
- [ ] `ForestInventory`와 `UserInventory` 통합 또는 역할 분리
- [ ] 숲 아바타 코드와 상점 아이템 ID 매핑
- [ ] 보상 지급 시 원장·잔액의 단일 트랜잭션 처리
- [ ] 구매·보상 요청의 중복 처리 방지 키 적용
- [ ] 그룹에 건강정보·예측 결과가 노출되지 않는지 테스트

## 3. 우선순위와 의존성

1. **P0:** 동의 철회 FE 연결과 철회 후 서버 차단
2. **P0:** 인증·그룹 ID 전달 계약
3. **P1:** `ApiForestAdapter` 전환과 오류 처리
4. **P1:** 지갑·인벤토리·아바타 단일 책임 확정
5. **P2:** 슬로건 수정과 세부 편의 기능

데이터 단일 책임과 인증 계약이 확정되기 전에는 `localStorage` 데이터를 서버 DB로 자동 마이그레이션하지 않는다.

## 4. 완료 기준

- [ ] 프론트에서 동의를 철회하고 재동의할 수 있다.
- [ ] 철회 직후 신규 검진·예측·챌린지가 차단되고 재로그인 후에도 상태가 유지된다.
- [ ] 로그인 사용자와 현재 그룹을 식별해 숲을 연다.
- [ ] 새로고침·재로그인·다른 기기에서 재화·인벤토리·아바타·숲 상태가 일치한다.
- [ ] 구매·보상·오브젝트 배치·제거가 서버 API를 통해 처리된다.
- [ ] API 장애를 로컬 성공으로 위장하지 않는다.
- [ ] 건강정보와 예측 결과가 가족·친구 그룹에 공유되지 않는다.
- [ ] 관련 단위·통합·E2E·의료 안전 테스트와 API 문서를 함께 갱신한다.

## 5. 확인이 필요한 결정

- 철회 시 진행 중인 챌린지를 즉시 종료할지, 기록만 잠그고 종료 상태로 보관할지
- 기존 건강정보·예측 결과의 보관기간 및 삭제 요청 처리 방식
- 슬로건의 최대 길이·금칙어·공백 정규화 기준
- 레거시 `ForestAvatar.carrot_balance`, `ForestInventory`의 제거 시점
- 기존 `localStorage` 데모 상태를 폐기할지, 1회성 가져오기 기능을 제공할지
