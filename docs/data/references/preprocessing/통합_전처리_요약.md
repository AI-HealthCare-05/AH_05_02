# 국민건강영양조사 통합·전처리 요약

## 1. 목적

만성생활습관 챌린지의 대사질환 위험 분석과 개인화 기능 검토를 위해, 국민건강영양조사 원시자료를 연도별로 통합하고 대사 건강 관련 항목을 같은 이름으로 정리했다.

## 2. 입력 자료

- 위치: `국민건강영양조사/xlsx`
- 파일: `hn98_all.csv`부터 `hn24_all.csv`까지 21개 파일
- 조사연도: 1998, 2001, 2005, 2007~2024년
- 원본 행 수: 251,455건

> 연도마다 참여자 ID가 독립적이므로, 같은 사람을 기준으로 가로 결합하지 않았다. 모든 자료를 연도 정보와 함께 세로로 이어 붙였다.

## 3. 전처리·병합 방식

1. 모든 CSV의 인코딩과 헤더를 확인했다. 원본 파일은 수정하지 않았다.
2. 연도별 대소문자가 다른 참여자 ID는 출력하지 않고, 각 행에 익명 `record_key`를 새로 부여했다.
3. 연도·원본 파일명·원본 행 번호를 함께 저장하여 추적 가능하도록 했다.
4. 연도별로 이름이 다른 일부 측정값을 공통 이름으로 맞췄다.
   - 예: `HE_SBP1`/`HE_sbp` → `systolic_bp`
   - 예: `HE_DBP1`/`HE_dbp` → `diastolic_bp`
   - 예: `HE_HDL`/`HE_HDL_st2` → `hdl_cholesterol_mg_dl`
5. 빈 문자열과 공백만 빈 값으로 정리했다. 수치 변환, 이상치 제거, 결측 대체는 아직 하지 않았다.

## 4. 결과 파일

- `knhanes_metabolic_core_1998_2024.csv`
  - 251,455행, 26개 열
  - UTF-8 BOM 인코딩으로 저장되어 Excel에서 한글이 깨지지 않도록 했다.
- `knhanes_metabolic_core_1998_2024_merge_report.json`
  - 연도별 행 수, 실제 매핑된 원본 컬럼, 항목별 비어 있지 않은 값 수를 기록했다.

## 5. 통합 컬럼

| 구분 | 컬럼 |
| --- | --- |
| 추적 정보 | `record_key`, `source_survey_year`, `source_file`, `source_row_number` |
| 기본 정보 | `sex`, `age`, `region`, `town_t` |
| 신체 측정 | `height_cm`, `weight_kg`, `bmi`, `waist_cm` |
| 혈압·혈액검사 | `systolic_bp`, `diastolic_bp`, `fasting_glucose_mg_dl`, `hba1c_pct`, `total_cholesterol_mg_dl`, `hdl_cholesterol_mg_dl`, `triglyceride_mg_dl` |
| 생활습관·가족력 | `aerobic_activity`, `current_smoking`, `stress_level`, `family_history_diabetes` |
| 영양 | `energy_kcal`, `sodium_mg`, `sugar_g` |

## 6. 반드시 이어서 할 작업

- 연도별 코드북을 확인해 `8`, `88`, `888`, `9999` 등의 무응답·모름·해당없음 코드를 `NaN`으로 처리한다.
- 모델 타깃을 확정한다. 예: 대사증후군 위험 범주, 공복혈당 이상 여부, 고혈압 위험 여부.
- 타깃 정의에 필요한 약물 복용·진단 변수와 측정 기준을 코드북에서 검증한다.
- 분석 대상 연도와 연령(예: 만 19세 이상)을 확정한 뒤 결측률·이상치·표본 수를 다시 확인한다.
- 학습/검증/테스트 분할은 개인 중복 가능성과 조사연도 차이를 고려해 설계한다.

## 7. 유의사항

- 이 파일은 연구·프로젝트용 비식별 조사자료이며, 실제 사용자의 진단·처방을 위한 데이터가 아니다.
- 연도별 설문 문항과 코드 의미가 달라, 단순히 값만 비교하면 잘못 해석할 수 있다.
- 특히 약물 복용, 당뇨·고혈압 진단 여부, 공복 상태, 결측 코드는 모델링 전에 코드북 근거로 확정해야 한다.
