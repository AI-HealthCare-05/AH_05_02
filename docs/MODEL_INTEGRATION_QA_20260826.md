# 실제 모델 연동 QA 체크리스트 — 2026-08-26

## 1. 연동 전

- [ ] 후보 모델은 동일 참여자 분할로 재현했다.
- [ ] Recall·Specificity·AUPRC·AUROC·F1·Brier와 클래스 비율을 기록했다.
- [ ] 임계값은 Test가 아닌 Validation에서 선택했다.
- [ ] 미래 진단·약물·후속 조사값 등 누수 변수가 없다.
- [ ] artifact·전처리기·메타데이터·checksum·롤백 후보가 준비되었다.
- [ ] 모델 바이너리와 원본 데이터가 Git에 포함되지 않았다.

## 2. 계약 검증

- [ ] 특성 이름과 순서가 8개 공통 입력 계약과 정확히 일치한다.
- [ ] 범주·결측·단위 변환이 학습 파이프라인과 추론에서 같다.
- [ ] `model_version`, `feature_schema_version`, `threshold_version`이 모두 존재한다.
- [ ] 활성 모델의 검증 연령 밖 사용자는 모델 예측에서 제외된다.
- [ ] 고정 입력의 로컬 추론 결과와 Provider 결과가 허용 오차 내에서 같다.

## 3. API·Worker·DB

- [ ] 예측 요청은 HTTP 202와 `job_id`를 반환한다.
- [ ] 상태가 `queued → running → succeeded` 또는 `failed`로 전이한다.
- [ ] 중복 실행·존재하지 않는 검진·타인 검진 접근을 차단한다.
- [ ] Redis 장애·Worker 오류·시간초과를 실패 이력과 재시도 정보로 남긴다.
- [ ] 성공 시 `Prediction`에 사용자·검진·작업·버전·결과가 저장된다.
- [ ] 로그·큐 메시지에 원본 건강정보와 개인정보가 노출되지 않는다.

## 4. 화면·의료 안전

- [ ] 대기·실행·성공·실패 상태를 색상 외 글자와 아이콘으로 표시한다.
- [ ] 승인되지 않은 모델은 확률·위험 범주·SHAP 설명을 공개하지 않는다.
- [ ] 승인 모델도 결과를 진단 또는 확정적 발병확률로 표현하지 않는다.
- [ ] 기진단·경고 증상 사용자는 예측이 생성되지 않고 의료 안내를 받는다.
- [ ] 고위험 안내가 챌린지보다 먼저 노출된다.
- [ ] 약물 시작·중단·용량 변경을 추천하지 않는다.

## 5. E2E·운영

- [ ] 가입 → 동의 → 적합성 → 건강정보 → 예측 → 결과 → 챌린지 → 대시보드가 완료된다.
- [ ] 개발 모드와 Docker 모드에서 핵심 흐름을 각각 재현한다.
- [ ] 단위·통합·의료 안전 테스트와 Ruff가 통과한다.
- [ ] 실패 시 개발 Provider 또는 직전 승인 모델로 롤백할 수 있다.
- [ ] 실행 명령·환경변수·검증 결과를 릴리즈 노트에 기록한다.
