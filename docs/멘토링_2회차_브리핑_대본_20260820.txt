[슬라이드 1 — 인사와 목적]
안녕하세요. AI 헬스케어 5기 2조입니다.
오늘은 지난 멘토링에서 받은 피드백을 저희가 어떤 선택과 구현 기준으로 바꿨는지, 그리고 실제 데이터 실험에서 무엇을 확인했는지 간단히 보고드리겠습니다.
마지막에는 다음 구현을 위해 멘토님께 꼭 확인받고 싶은 네 가지 질문을 드리겠습니다.

[슬라이드 2 — 1회차 피드백의 반영]
첫 번째로 범위를 당뇨병 하나로 좁혔습니다. 고혈압까지 동시에 확장하기보다 예측, 설명, 챌린지의 연결 완성도를 높이는 방향입니다.
두 번째로 예측 문제를 현재 상태 분류가 아니라 기준 시점 미진단자의 미래 신규 발병 이진분류로 명확히 했습니다.
세 번째로 서비스 이용 연령과 핵심 타깃 연령, 모델의 실제 적용 연령을 분리했습니다.
마지막으로 원시 확률보다 위험 범주를 우선하고, 기진단자는 모델 입력과 개인화 추천에서 제외하도록 안전 기준을 세웠습니다.

[슬라이드 3 — 서비스 대상과 모델 적용 범위]
연령은 한 숫자로 정리하지 않고 세 단계로 나눴습니다.
만 19세 이상이면 서비스를 이용할 수 있지만, 핵심 기획 타깃은 40대 이상 당뇨병 미진단자입니다.
실제 개인화 예측은 활성 모델 카드에서 검증된 연령과 모집단에만 제공합니다.
특히 KLoSA 최초 표본 특성상 40세에서 44세는 근거가 부족하므로 KLoSA 단독 미래 예측은 막고, 안내와 일반 건강교육만 제공하는 방향입니다.
기진단자, 경고 증상 보유자, 모델 적용 범위 밖 사용자는 예측 작업을 생성하지 않고 검사 또는 의료기관 안내로 전환합니다.

[슬라이드 4 — 축소 베이스라인 결과]
공통 변수 다섯 개와 축소 표본으로 베이스라인을 먼저 돌렸습니다.
KLoSA 로지스틱 회귀는 AUROC 0.641, AUPRC 0.042였고, 국민건강영양조사 로지스틱 회귀는 AUROC 0.745, AUPRC 0.108이었습니다.
두 데이터 모두 로지스틱 회귀가 랜덤포레스트보다 판별력이 높았습니다.
다만 양성 비율이 낮아 AUPRC가 낮고 확률 보정도 충분하지 않습니다.
또 KLoSA는 미래 신규발병, 국민건강영양조사는 현재 위험 신호이므로 두 데이터의 숫자를 직접 비교하지 않습니다.
따라서 지금 결과는 모델 확정이 아니라 파이프라인과 위험을 조기에 확인한 결과입니다.

[슬라이드 5 — 기술 계약]
기획 결정은 문서에만 두지 않고 화면, API, DB가 공유하는 기술 계약으로 연결했습니다.
적합성 검사는 프론트 안내에만 의존하지 않고 서버에서도 기진단, 동의, 연령을 다시 확인합니다.
예측 작업 경로는 /api/v1/prediction-jobs로 통일했고, 상태는 queued, running, succeeded, failed 네 가지입니다.
Redis에는 빠르게 사라져도 되는 단기 작업 상태를, DB에는 요청과 완료·실패, 모델 버전과 결과 같은 최소 이력을 보존합니다.
결과 범주는 검증된 threshold version이 승인된 경우에만 사용자에게 노출합니다.

[슬라이드 6 — 현재 진행 상황]
현재 요구사항과 API 명세 v2.0, 의료 안전 문구, 추적성 문서와 축소 베이스라인까지 준비됐습니다.
문서 계약 테스트는 11개가 통과했고, 베이스라인 작업 브랜치에서는 17개 테스트를 통과했습니다.
이제 남은 핵심은 전체 표본과 연령 하위집단 검증, 보정과 임계값 결정, 실제 API·DB·프론트 연결, 그리고 Docker 환경에서 세로 흐름을 끝까지 통과시키는 것입니다.

[슬라이드 7 — 멘토님께 받고 싶은 피드백]
이번 멘토링에서는 네 가지를 확인받고 싶습니다.
첫째, 현재 AUPRC가 낮더라도 문제 정의의 일관성을 위해 KLoSA 미래 발병 예측을 유지하는 것이 맞는지입니다.
둘째, 근거가 부족한 40세에서 44세에게는 예측 대신 안내만 제공하는 방식이 적절한지입니다.
셋째, 임계값을 정할 때 놓치는 고위험자를 줄이는 민감도와 불필요한 경고를 줄이는 특이도 중 어떤 비용을 더 크게 봐야 하는지입니다.
넷째, 현재 규모에서도 Redis 비동기 워커 구조를 유지하는 것이 실무 경험과 MVP 균형에 적절한지 피드백을 부탁드립니다.
오늘 결정된 내용은 모델 카드와 API, 화면, 테스트에 바로 반영하겠습니다.
