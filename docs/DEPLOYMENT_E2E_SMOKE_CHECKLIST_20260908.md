## 2. 배포 전 E2E

### 정상 사용자

- [ ] 첫 화면에서 신규 가입과 기존 로그인이 구분된다.
- [ ] `terms_agreed=true`를 포함한 회원가입이 성공한다.
- [ ] 성별·생년월일이 프로필 API에 저장된다.
- [ ] 응급증상·기진단 없음 사용자가 건강정보 설문을 완료한다.
- [ ] 건강정보 저장 후 오늘이와 내일이 작업 ID를 각각 받는다.
- [ ] 두 작업이 `queued → running → succeeded`로 전환된다.
- [ ] 결과 화면에 각 모델의 목적과 기간이 구분된다.
- [ ] 승인되지 않은 확률·범주는 노출되지 않는다.
- [ ] 챌린지 선택·인증 후 대시보드와 리포트에 반영된다.
- [ ] 건강정보 수정 후 다시 분석할 수 있다.

### 예외·의료 안전

- [ ] 만 19세 미만은 분석하지 않고 이용 제한을 안내한다.
- [ ] 당뇨 기진단자는 신규 발병 예측을 실행하지 않는다.
- [ ] 응급증상 `예` 선택 시 분석보다 119·응급실 안내를 우선한다.
- [ ] 필수값 누락과 허용범위 오류가 입력 항목 가까이에 표시된다.
- [ ] 오늘이·내일이 결과가 다를 때 평균하거나 상쇄하지 않는다.
- [ ] 낮은 결과를 `정상 확정` 또는 `질환 없음`으로 표현하지 않는다.
- [ ] Worker 중단 시 임의 성공 결과를 만들지 않는다.
- [ ] 시간초과 시 입력을 보존하고 실패 사유·재시도 경로를 제공한다.

### 비동기·성능

- [ ] 동일 `job_id`의 생성·시작·완료 시각과 Worker 이름을 기록한다.
- [ ] 큐 대기시간, 모델 로딩시간, 추론시간, DB 저장시간을 구분한다.
- [ ] 최초 요청과 두 번째 요청의 처리시간을 비교한다.
- [ ] 오늘이·내일이 개별 실패 시 완료된 결과는 유지된다.
- [ ] 중복 클릭으로 동일 분석 작업이 과도하게 생성되지 않는다.

## 3. 배포 직후 Smoke Test

- [ ] 서비스 기본 URL이 HTTPS로 열린다.
- [ ] `/api/health`가 정상 응답한다.
- [ ] `/docs` 또는 운영에서 허용한 API 문서 경로가 열린다.
- [ ] 프론트 정적 파일·CSS·이미지·한글 폰트가 정상 표시된다.
- [ ] FastAPI, MySQL, Redis, AI Worker 컨테이너가 Healthy 상태다.
- [ ] DB 마이그레이션이 최신 버전까지 적용됐다.
- [ ] 테스트 계정 가입·로그인이 성공한다.
- [ ] 건강정보 1건 저장이 성공한다.
- [ ] 오늘이·내일이 테스트 작업이 각각 완료된다.
- [ ] Worker 로그에 Artifact 누락·SHA 불일치·OpenMP 오류가 없다.
- [ ] 챌린지 조회·선택·인증 API가 응답한다.
- [ ] 지도 기능은 위치 권한 거부와 기본 시연 좌표 모두 처리한다.
- [ ] 비밀키·DB 비밀번호·개인정보가 응답과 로그에 노출되지 않는다.

## 4. 배포 중단·롤백 조건

다음 중 하나라도 발생하면 신규 배포를 중단하고 이전 안정 버전으로 되돌린다.

- 회원가입·건강정보 저장·예측 요청 중 하나가 전체 사용자에게 실패한다.
- Worker가 작업을 소비하지 못하거나 실제 모델 Artifact를 로드하지 못한다.
- 연구용 결과가 승인된 결과처럼 공개된다.
- 응급·기진단 분기가 작동하지 않는다.
- DB 마이그레이션 실패 또는 데이터 손상 가능성이 발견된다.
- 인증 우회, 비밀정보 노출 등 보안 문제가 발견된다.
