# 2026-09-09 프론트 변경 공유 메모

## 한 줄 요약

9/9 기준 프론트는 온보딩 이후 핵심 흐름을 `당근의 숲` 세계관에 맞춰 재정리했고, 건강정보 입력 → 분석 대기 → 결과 확인 → 챌린지 선택/기록 → 대시보드/리포트/건강도구/함께하기 화면까지 8022에서 이어서 확인할 수 있도록 구성했습니다.

## 1. 현재 프론트에서 확인 가능한 주요 흐름

### 회원가입·로그인

- 회원가입 화면을 `당근의 숲 문앞/집 안내판` 콘셉트로 재구성했습니다.
- 회원가입 요청에 `terms_agreed` 포함 여부를 확인했습니다.
- 닉네임 입력을 추가했습니다. 현재 확정 화면에는 `○○의 집` 실시간 미리보기 영역이 없으며, 가입 후 프로필 이름으로 저장합니다.
- 가입 직후 닉네임이 `/users/me/profile`의 `name`으로 저장되도록 연결했습니다.
- 이메일, 비밀번호, 동의, 생년월일, 성별, 비밀번호 보기 기능은 유지했습니다.
- 관련 프론트 단위 테스트 10개를 통과했습니다.

### 건강정보 입력

- 기본정보/생활습관/세부 건강정보를 8개 캐러셀 버튼으로 나누어 입력하도록 재구성했습니다.
- 입력 구분은 아래 순서로 정리했습니다.
  1. 체형 정보: 키, 몸무게, 허리둘레
  2. 혈당·혈압: 공복혈당, 수축기혈압, 이완기혈압
  3. 음주: 현재 음주 유무, 음주 빈도
  4. 생활상태: 흡연 상태, 주관적 건강상태
  5. 운동: 규칙적인 운동 유무, 걷기 일수, 주당 운동 일수, 1회 운동 시간
  6. 가족력: 고혈압 가족력, 당뇨병 가족력
  7. 영양정보: 어제 식사 횟수, 열량, 단백질, 지방, 탄수화물, 나트륨
  8. 지역·사회경제: 거주 지역, 도시/읍면 구분, 최종 학력, 소득 분위, 고용 상태
- 입력 완료 후 바로 분석하지 않고, `입력사항 확인` 전용 화면에서 한 번 더 확인한 뒤 분석하도록 변경했습니다.
- 입력사항 확인 화면은 카드형 3×3 구성으로 정리했고, 입력 당시 순서를 유지했습니다.
- 건강정보 입력 화면의 장식 헤더는 유지하되, 중복되는 작은 제목과 불필요한 장식은 정리했습니다.
- 현재 화면에서 라벨 앞 당근 아이콘은 제거했고, 카드 텍스트 정렬과 높이를 맞췄습니다.

### 분석 중 화면

- 분석 중/완료/실패 화면은 같은 방 배경을 사용하도록 정리했습니다.
- 대기/분석중/완료/실패 카드 크기를 동일하게 맞췄습니다.
- 진행률 숫자는 위험 확률로 오해될 수 있어 표시하지 않도록 했습니다.
- 실패 시 문구는 `분석을 완료하지 못했습니다. 다시 시도해 주세요.`로 정리하고, 바로 아래에 `다시 시도하기` 버튼을 배치했습니다.
- 완료 시 문구는 `결과 화면에서 위험 범주와 다음 행동을 확인해 주세요.`로 정리했습니다.

### 결과 확인 화면

- 결과 확인 화면도 같은 방 배경을 사용하도록 구성했습니다.
- 상단 문구는 `오늘,미래의 신호 결과를 확인해요`로 정리했습니다.
- 개발 확인용 안내, 화면 확인용 주의, 운영 승인 관련 더미 문구는 제거했습니다.
- `오늘의 신호`와 `미래의 신호`를 구분해서 보여주되, 설명보다 제목이 더 잘 보이도록 글자 크기를 조정했습니다.
- 미래 신호 그래프는 세로 막대형에서 반원 그래프 형태로 바꿨습니다.
- 반원 그래프 오른쪽에는 추후 점수/설명 영역을 위해 `점수표시대기` 공간을 마련했습니다.
- 높은 위험 결과에서 `검사 상담안내 보기` 클릭 시 아래 펼침이 아니라 팝업으로 안내가 뜨도록 변경했습니다.

### 챌린지 선택·기록

- 결과 화면의 다음 CTA는 챌린지 선택 화면으로 이어지도록 구성했습니다.
- 챌린지 선택 화면 제목은 `오늘의 실천을 골라요`로 정리했습니다.
- 챌린지 선택 화면은 숲 배경을 사용합니다.
- 챌린지 기록 화면도 같은 숲 배경 위에서 보이도록 적용했습니다.
- `이유 기록하고 조정안 보기`를 누르면 아래에 큰 나무 안내판 스타일의 조정안 카드가 뜨도록 구성했습니다.
- 개인 챌린지 사용자는 당근의 숲 버튼 클릭 시 `/forest?demo=1`로 이동하도록 시연 흐름을 보강했습니다.

### 대시보드·리포트·건강도구·함께하기

- 대시보드 홈, 건강도구, 함께하기, 리포트 탭별 배경 이미지를 분리 적용했습니다.
- 리포트 탭은 중앙에 리포트/그래프 영역을 두고, 오른쪽 탁자 옆에 혈당이 캐릭터를 배치하는 방향으로 정리했습니다.
- 건강도구 탭은 온실/작업실 배경을 사용합니다.
- 건강도구의 워치 카드에서 `워치 연동` 큰 제목은 숨기고, 카드 하나만 보이도록 이중 배경을 제거했습니다.
- 함께하기 탭은 별도 숲 쉼터 배경을 사용합니다.

## 2. 8022 화면 확인 URL

- 전체 진입: `http://127.0.0.1:8022/`
- 로그인 진입: `http://127.0.0.1:8022/?auth=login`
- 건강정보 입력: `http://127.0.0.1:8022/?preview=health-room`
- 분석 중: `http://127.0.0.1:8022/?preview=analysis-status&status=running`
- 분석 완료: `http://127.0.0.1:8022/?preview=analysis-status&status=succeeded`
- 분석 실패: `http://127.0.0.1:8022/?preview=analysis-status&status=failed`
- 결과 확인: `http://127.0.0.1:8022/?preview=results`
- 챌린지 선택: `http://127.0.0.1:8022/?preview=challenge-forest`
- 챌린지 기록: `http://127.0.0.1:8022/?preview=challenge-record`
- 리포트 탭: `http://127.0.0.1:8022/?preview=report-forest`
- 건강도구 탭: `http://127.0.0.1:8022/?preview=health-tools`
- 함께하기 탭: `http://127.0.0.1:8022/?workspace=together`
- 당근의 숲 개인 시연: `http://127.0.0.1:8022/forest?demo=1`

> `preview` URL은 특정 화면을 바로 보기 위한 확인용입니다. 전체 연결 흐름은 기본 진입 또는 로그인 진입에서 확인하는 것이 좋습니다.

## 3. 빛샘님 9/9 업무와 연결한 부분

### 건강정보 RAG·퀴즈

- 건강도구 탭의 건강교육/퀴즈 영역은 `/api/v1/health-education/questions` 응답을 기준으로 표시합니다.
- 프론트에서 확인하는 주요 응답값은 아래와 같습니다.
  - `answer_status`
  - `answer`
  - `citations`
  - `medical_notice`
- 근거가 없는 답변, 출처 누락, 의료 판단으로 오해될 수 있는 응답은 안전 안내/재시도 상태로 처리하는 방향입니다.
- 진단, 처방, 복약 변경처럼 의료 판단으로 보일 수 있는 문구는 프론트 표시에서 주의가 필요합니다.

### 웨어러블 Apple 정제 결과

- Apple Health 정제 결과가 일별 요약 형태로 들어올 수 있도록 건강도구 탭에 웨어러블 일별 요약 입력 구조를 열어두었습니다.
- 공통 저장 기준은 걸음, 활동, 수면, 심박 요약을 중심으로 맞췄습니다.

## 4. 준혁님 9/9 업무와 연결한 부분

### Android 웨어러블 정제 결과

- Android Health Connect/Samsung Health 정제 결과가 Apple과 같은 공통 일별 컬럼으로 들어오는 것을 전제로 프론트 입력/저장 필드를 맞췄습니다.
- 현재 프론트 수동 입력/저장 기준 필드는 아래와 같습니다.
  - `steps`
  - `active_minutes`
  - `sleep_minutes`
  - `resting_heart_rate`
- 워치 연결 버튼은 운영 OAuth가 아니라 `development_mock` 연결을 생성하는 시연용 흐름입니다.
- 저장 요청은 `/api/v1/wearables/connections` → `/api/v1/wearables/daily-summaries/import` 순서로 연결했습니다.
- scopes는 `activity`, `sleep`, `heart_rate`로 확장했습니다.

### 모델 분석시간 최적화 관련

- 준혁님 9/9 메모 기준으로, 현재 환경에서는 프론트 요청 병렬화가 무조건 이득이라고 보기 어렵습니다.
- Worker 수, 큐 지연, 공유 상태 갱신 검증이 필요하므로 프론트 요청 정책은 추가 변경하지 않았습니다.
- 현재는 화면 상태 구분과 실패/재시도 UX를 우선 정리했습니다.

## 8. 아직 추가 확인이 필요한 것

### 실제 API·Worker 검증

- 실제 계정으로 회원가입 → 건강정보 입력 → 분석 요청 → 결과 확인 → 챌린지 선택 → 기록 → 리포트까지 원사이클 확인
- 예측 요청의 대기, 완료, 실패, 시간초과 상태가 실제 Worker 응답과 맞는지 확인
- 일부 모델 실패 시 성공 결과는 유지하고 실패 모델만 재시도되는지 확인
- 현재 건강 신호/미래 신호의 운영 승인 플래그와 수치·확률 비노출 규칙 재검증

### 챌린지·리포트

- 실제 계정으로 챌린지 선택 → 완료 화면 → 기록 → 건강홈 상태 복원 확인
- 일부 일일 기록 실패 시 개별 실패 카드로 유지되는지 확인
- 리포트의 이번 주/지난 4주/전체 기간 API 응답 확인
- 리포트 빈 결과, 실패, 재시도 상태 확인
- 웨어러블 일별 요약을 리포트에 함께 보여줄지, 건강도구와 분리할지 정책 결정

### 건강도구·건강교육

- RAG 실제 답변, 출처, 빈 응답, 실패, 재시도 상태 확인
- 퀴즈 해설과 출처 표시 방식 최종 확인
- 실제 Apple/Android 원본 파일 업로드 또는 OAuth 연동 정책 결정
- wearable connection id를 재사용할지, 매번 생성할지 백엔드 정책 확인

### 개인정보·함께하기·숲

- 건강정보 동의 철회/재동의 화면과 API 호출 연결 확인
- 동의 철회 직후 건강정보 저장, 예측, 신규 챌린지 차단 확인
- 받은 초대 조회/수락, 초대코드 발급 화면 연결 확인
- 실제 초대 계정 2개로 발급 → 조회 → 수락 검증
- 숲 진입 전 인증, 그룹 선택, `ApiForestAdapter` 실제 서버 데이터 연결 확인
- 새로고침, 다른 기기, API 실패 시 복원 동작 확인
