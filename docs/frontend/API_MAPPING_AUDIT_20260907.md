## 1. 빛샘 기록과 실행 코드의 차이

참조: [API 상태](https://app.notion.com/p/3d4caf5650aa8047904af7bc195a6a4c), [요청·응답](https://app.notion.com/p/3d4caf5650aa8088a8d4d642015dfd2a), [RAG 추가 자료](https://app.notion.com/p/3d4caf5650aa80398344fb91216e5b06). 이전 대화에서 읽은 원문 기준이며 새 PR의 머지 여부는 이번 범위에 포함하지 않았다.

| 항목 | 8022에서 확인한 상태 |
|---|---|
| 약관 동의 DB 저장 | 프론트 전송은 존재. `app/models/users.py`에 terms_agreed 컬럼이 없고 AuthService.signup의 저장 인자에도 없음. 빛샘 수정본이 이 코드에 반영되지 않음. 건강정보 동의 `/consents`와 별개 문제. |
| AI jobs 라우터 | `/api/openapi.json`에 `/api/v1/ai-jobs` 없음. v1 등록 코드에도 없음. |
| 작업 상태/공통 오류 | `AIJobResponse.status`가 여전히 str. `error_detail` 공통 헬퍼 없음. 시설 API 오류도 detail 문자열 형태. 프론트는 문자열과 새 구조화 응답 둘 다 처리함. |
| 내일이 전망 지점 | `ai_worker/handlers.py::_build_age_risk_forecast`에는 지점별 signal_level 없음. 별도 연구용 `_run_s2_future_model`에는 있음. 두 경로를 같은 구현으로 보지 않음. 실제 새 모델 추론은 이번에 실행하지 않음. |
| 미래 전망 UI | 프론트는 모레노 MVP 제외 때 risk-forecast-panel/age-risk-chart와 지점 렌더링까지 제거됨. 범주 요약은 남지만 points[].signal_level이 와도 지점 화면은 나오지 않음. 내일이 지점 표시를 유지할지 범위 재확인 필요. |
| 건강교육 자료 | `src/rag/engine.py`의 기존 문서 4개를 키워드로 조회. 빛샘이 추가했다고 기록한 운동/식이/합병증 등 5개 문서 세트는 없음. |

DB 장애 복구용 실행기는 형제 프로젝트에서 DB 접속 정보만 가져온다. 외부 API 키·모델 설정을 복사하지 않았으므로 DB 연결 복구가 카카오/NEMC 연동 완료를 의미하지 않는다.

## 2. 실제 서버 API 응답

- 가상 계정 하나를 만들고 로그인하여 검사했다. 개인 위치 대신 서울시청 좌표를 사용했다. 건강검진/모델 작업/챌린지 기록은 만들지 않았고 119·기관에 전화하지 않았다.
- 의료기관 GET: HTTP 200, provider_kind=development, data_source=development_mock, 3개 샘플 반환. 실제 병원 검색 성공이 아님. 화면 주소에는 개발용 목업 표시가 있지만, 결과 제목·정보 출처·전화 링크가 일반 검색 결과처럼 표시됨. 실사용/시연 전 샘플을 분명히 구분하거나 차단해야 함.
- 응급기관 GET: HTTP 502, NEMC_SERVICE_KEY 미설정. 현재 환경의 실제 응급기관 검색은 불가.
- 건강교육 POST: 걷기 질문은 grounded + 출처 1개, 무관 질문은 insufficient_evidence, 약 변경 질문은 medical_safety_refusal. 세 요청 모두 HTTP 200 및 의료 안내 포함. retrieval_method=approved_document_keyword_v1.

## 3. 브라우저 및 응답 계약 검사

`tests/frontend/api_mapping_audit_20260907.cjs`: 1440/380px, 30개 확인 통과 및 2개 문제 발견.

- 일반/응급 기관: 위치 거부·시간초과, 정상 결과·빈 결과·503 UI 통과. 위치 실패 때 검색 API 요청하지 않음. 응급기관 상태 변화 중 119 링크 유지. 실제 지도 SDK는 이 테스트에서 제외하여 목록/UI만 검사함.
- Q&A: 실제 서버가 반환한 세 종류 응답을 화면에 재생해 답변/출처/거절 안내 검사. 실패 후 질문 보존·버튼 복구·재시도 통과. 검사 화면에 JS 오류·가로 넘침 없음.
- 발견: HTTP 200 빈 객체 응답에서 Q&A가 `done` 및 ‘건강교육 정보를 확인했어요’로 표시됨. 답변 없음/형식 오류는 성공과 구분해야 함. 두 화면 크기에서 재현, 아직 수정하지 않음. 진단 스크립트의 실패 exit code는 이 문제를 보존하기 위한 것임.
- `api_response_contract.test.cjs` 신규 6개 통과: low/caution/high→낮음/주의/높음, 알 수 없는 신호 보류, ML 오류코드 변환·retryable 보존·문자열/배열 오류·오프라인.
- 기존 integration_refresh/partial_analysis와 합계 21개 단위 검사 통과. 승인된 미래 결과가 현재 결과를 덮어쓰지 않음, 실패 모델만 재시도, 연구 전망 차단 유지 확인.
