# 백엔드 계약 정렬 후 흐름 재점검

## 현재 반영한 계약

- `POST /api/v1/auth/signup`에 `email`, `password`, `gender`, `birth_date`를 전송한다.
- 이름은 가입 화면과 가입 API 요청에서 수집하지 않는다.
- 성별·생년월일 수정은 `PATCH /api/v1/users/me`를 사용한다.
- 건강정보 동의는 로그인 후 `POST /api/v1/consents`로 저장한다.
- 기존 회원은 `GET /api/v1/eligibility-checks/latest`로 이전 이용 가능 확인 기록을 조회한다.

## 팀장 확인 연령별 이용 범위

| 만 나이 | 제공 기능 | 프론트 이동 |
|---|---|---|
| 14~18세 | 생활습관 챌린지 | 이용 가능 확인 후 챌린지 선택 |
| 19~44세 | 현재 건강 신호 + 생활습관 챌린지 | 건강정보 저장 → 현재 건강 신호 결과 → 챌린지 |
| 45세 이상 | 현재 건강 신호 + 미래 발병 위험 + 생활습관 챌린지 | 건강정보 저장 → 미래 발병 위험 예측 → 결과 확인 → 챌린지 |

- 미래 발병 위험은 정확한 발병 시점을 예측한다는 의미가 아니다.
- `19~44세 현재 건강 신호`는 백엔드가 전달하는 결과만 표시하고, 응답이 없을 때 정상·위험 범주를 임의 생성하지 않는다.
- 프론트는 `current_health_signal`, `current_health_assessment`, `health_signal` 응답 키를 순서대로 수용하도록 연결 지점을 준비했다. 최종 키가 확정되면 하나로 통일한다.

## 나중에 흐름을 다시 확인할 부분

- [ ] 가입 화면에서 받은 성별·생년월일을 이용 가능 확인 화면에서 다시 입력받지 않고, 요약+수정 링크로 보여줄지 결정한다.
- [ ] 계정은 생성됐지만 건강정보 동의 저장이 실패한 사용자의 재진입 흐름을 정한다.
- [ ] 화면에서 받는 서비스 이용약관·개인정보 필수 동의는 현재 가입 API 필드로 저장되지 않으므로, 저장 API와 버전 관리 방식을 확정한다.
- [x] 만 14~18세는 챌린지만, 만 19~44세는 현재 건강 신호와 챌린지, 만 45세 이상은 미래 발병 위험까지 제공하는 계단식 정책으로 정리했다.
- [ ] 백엔드의 현재 건강 신호 최종 엔드포인트·응답 키·상태값을 수령한 뒤 임시 호환 키를 단일 계약으로 정리한다.
- [ ] 성별 enum이 `FEMALE`/`MALE` 두 가지로만 정의된 부분을 요구사항과 다시 대조한다.
- [ ] 이용 가능 확인 기록의 만료 기간과 재확인 조건(진단 상태 변경 등)을 팀에서 정한다.
- [ ] 진행 중인 챌린지는 있지만 이용 가능 확인 기록이 없는 기존 데이터의 처리 기준을 정한다.
