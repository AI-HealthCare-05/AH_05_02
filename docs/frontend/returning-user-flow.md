# 기존 회원 재방문 흐름

## 결정 사항

- 신규 회원은 기존 `1 서비스 안내 → 2 가입·동의 → 3 이용 가능 확인 → 4 건강정보 입력 → 5 분석 결과 → 6 결과 확인 → 7 챌린지 → 8 대시보드` 흐름을 사용한다.
- 기존 회원은 로그인할 때마다 3~6단계를 반복하지 않는다.
- 진행 중인 챌린지가 있으면 로그인 후 8 대시보드로 바로 이동할 수 있다.
- 챌린지를 새로 고르거나 변경하려면 7 챌린지로 이동할 수 있다.
- 건강정보 수정은 선택 기능이며 4 건강정보 입력에서 저장한 뒤 8 대시보드로 돌아간다.
- 기존 회원의 건강정보 수정은 자동으로 새 예측을 요청하지 않는다.
- 기존 회원이 새 위험 확인을 요청할 때는 최신 안전·적합성 확인을 위해 3~6단계를 다시 진행한다.

## 화면 흐름

```text
2 기존 계정 로그인
├─ 진행 중 챌린지 있음 → 8 대시보드
├─ 챌린지 선택·변경 → 7 챌린지 → 8 대시보드
└─ 건강정보 수정 → 4 건강정보 입력·저장 → 8 대시보드
```

## 화면 원칙

- 로그인 완료 화면에서 `진행 중인 챌린지 계속하기`, `챌린지 선택·변경하기`, `건강정보 수정하기`를 분리한다.
- 진행 중인 챌린지가 없으면 대시보드 계속하기 버튼을 비활성화하고 챌린지 선택을 안내한다.
- 대시보드에서도 건강정보 수정과 챌린지 선택·변경으로 이동할 수 있다.
- 최근 예측 결과가 없는 사용자에게 임의의 위험 범주를 표시하지 않고 `최근 결과 없음`으로 표시한다.
- 재예측은 건강정보 저장과 분리하며, 사용자가 별도로 위험 확인을 요청하는 흐름에서만 실행한다.

## 연결 API

| 목적 | API |
| --- | --- |
| 기존 회원 로그인 | `POST /api/v1/auth/login` |
| 건강정보 동의 상태 확인 | `GET /api/v1/consents` |
| 진행 중 챌린지 확인 | `GET /api/v1/challenge-cycles/current` |
| 대시보드 요약 | `GET /api/v1/dashboard/summary` |
| 챌린지 진행 현황 | `GET /api/v1/dashboard/challenge-progress` |
| 건강정보 저장 | `POST /api/v1/health-checkups` |

건강정보 수정용 `PATCH` 계약이 추가되면 기존 기록을 갱신할지 새 건강기록을 생성할지 백엔드와 다시 확정한다.
