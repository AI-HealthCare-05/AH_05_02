# PR #23 — 9/7 프론트 1차 공유본

## 9/7 오후 추가 공유

- 서비스 소개를 짧은 제목·큰 그림·하단 설명으로 재구성. 소개 이동 메뉴, 50ms 전환, 모션 줄이기 설정을 지원한다.
- 마이페이지와 알림 메뉴 분리, 홈 바로가기 카드, 중복 기록 제목 제거, 로그인·회원가입 비밀번호 눈 아이콘 적용.
- 챌린지 4개 분류를 다시 누르면 접히도록 변경. 함께하기에는 제공된 당근의 숲 이미지를 게임 링크로 사용한다.
- 가입 후 프로필·동의 저장 복구, 모델별 부분 실패 시 성공 결과 보존/실패 요청만 재시도, 저장 기록 복원 개선.
- 모레노 연구 전망·시나리오 UI/연구 호출은 MVP에서 제외한다. 오늘이·내일이 결과는 분리하고 표시 승인 보호를 유지한다. 정리 중인 세부 입력은 임의 삭제하지 않는다.
- 주간 집계를 일일 기록으로 덮어쓰지 않으며, 미지원 4주/전체 PDF는 다른 기간 파일로 대체하지 않고 차단한다.
- 로컬 DB 연결용 실행 스크립트, 환경파일, 모델·게임 본체, 가상 사용자 데이터·스크린샷은 포함하지 않는다.
- 기존 약관 payload 테스트는 유지하고 새 폼의 중복 제출 방지 속성에 맞게 테스트 환경을 보완했다. 제거된 연구 전망을 요구하던 HTML 테스트는 MVP 제외·두 결과 분리·안전한 로컬 고정 예시를 검증하도록 갱신했다.
- 별도 8031 서버에서 푸시 사본의 소개/홈/비밀번호/챌린지 브라우저 테스트 통과. 프론트 단위 37개 통과. API 응답 제어 UI 검증이며 모델·운영 승인 검증은 아니다.
- 최종 검사: pytest 전체 122개, Ruff lint/format, 정적 이미지 참조 검사 통과. UI 회귀 19개·가입 복구 7개·안전 분기 6개·리포트 4개도 별도 서버에서 통과. 브라우저 테스트는 통제된 API 응답을 사용하며 실제 의료기관 외부 API나 전체 모델 서버 검증은 포함하지 않는다.

아래 1차 공유 당시의 검증 수치와 미완료 기록은 이력이다. 이번 추가 공유로 실제 전체 API E2E 또는 모든 연령/접근성 검증이 완료되는 것은 아니다.

## 팀원 실행과 연결 기준

```bash
git fetch origin
git switch codex/fe-ui-layout-polish
git pull --ff-only origin codex/fe-ui-layout-polish
```

작업 중인 수정이 있다면 먼저 보존하고 브랜치를 전환한다. `main`만 받으면 이번 UI가 반영되지 않는다.
의존성·기본 실행은 저장소 README를 따른다. 프론트는 FastAPI가 `/`와 `/static`으로 제공하며 API를 같은 서버의 `/api/v1`로 호출한다. HTML 파일을 직접 더블클릭해서 실행하지 않는다.

**이 PR만 받아서는 기존 8022 통합 환경의 실제 모델 추론이 재현되지 않는다.** 실제 분석에는 호환 백엔드·DB 마이그레이션·Redis Worker·별도 전달 모델 파일·환경 설정이 필요하다. 통합 검증 기준 커밋은 `codex/s2-api002`의 `6241603`이며 해당 백엔드는 이 PR에 포함하지 않았다. 기존 백엔드와의 실행 차이는 알려진 제한으로 보고한다.

모델 바이너리, `.env`, API 비밀키, QA 계정/건강정보 출력, 임시 스크린샷은 이번 커밋에서 제외한다. 모델 표시 승인 플래그를 켜서 오류를 우회하지 않는다.

## 확인한 범위

### 후속 CI 수정

- `tests/test_prototype.py`의 Ruff 포맷 오류를 정리했다.
- 회원가입 코드의 한 줄 문자열 검사를 제거하고, 실제 submit handler를 실행해 API 요청 JSON의 `terms_agreed`가 체크값(true/false)을 따르는지 검사한다. 하드코딩·누락·잘못된 전송값은 실패한다.
- pytest에서 Node.js의 해당 테스트를 실행하므로 로컬 테스트에도 Node.js 18 이상이 필요하다. 테스트는 가상 입력과 가로챈 API 호출만 사용하며 계정을 생성하지 않는다.
- 브라우저에서도 체크 시 `terms_agreed=true` 요청을 확인하고, 미체크 시 필수 항목 검증으로 요청이 차단됨을 확인했다.
- 수정 후 로컬 결과: Ruff check/format 전체 통과, pytest 전체 122개 통과, Node 단위 16개 통과, 브라우저 UI 17개 통과. GitHub 결과는 추가 푸시 후 별도로 확인한다.

푸시 대상 스냅샷에서 단위 14개, HTML·문서 pytest 39개, 브라우저 UI 16개·안전 분기 6개 및 320~1440px 헤더 검증을 통과했다. 브라우저 검증은 별도 로컬 8031에서 이 PR의 정적 파일을 제공하고 API 응답을 제어한 테스트이며, 실제 모델 성능·운영 검증이 아니다. 정적 이미지 참조 누락은 발견되지 않았다.

- 프론트 단위 회귀: `node --test tests/frontend/*.test.cjs`.
- JS 문법: `node --check src/frontend/app.js`.
- HTML/안전 문구 회귀: `python -m pytest -q tests/test_prototype.py tests/test_document_contracts.py`.
- Playwright: `tests/frontend/guest_header_qa.cjs`, `ui_ux_qa.cjs`, `safety_flow_qa.cjs`. 설치 환경에 따라 `PLAYWRIGHT_MODULE`, `CHROME_BIN`, 로컬 `QA_BASE_URL`을 지정한다.
- `local_flow_smoke.cjs`는 로컬 DB에 가상 계정·건강정보·챌린지를 생성한다. 실제 흐름 8단계 통과는 8022 통합 환경에서의 결과이며 PR #23의 이전 백엔드 전체 통과를 뜻하지 않는다.
