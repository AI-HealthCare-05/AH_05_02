# 9/7 팀 업무 확인 및 모레노 MVP 제외 — 1차

## 요약

사용자의 9/7 결정에 따라 모레노(생존·다년 전망)는 연구용으로만 남긴다. 프론트 MVP는 현재 위험 선별과 RF25 미래 신규발병 위험 선별을 유지한다. 노션은 읽기만 했으며 담당자들의 계획을 완료로 간주하지 않았다. Notion 자료 조사 스킬로 출처·완료 여부를 구분했고, 연결 도구가 팀 워크스페이스 페이지를 찾지 못해 로그인된 브라우저에서 해당 문서를 읽었다.

## 담당자 진행 상황 — 확인 시점의 노션 기준

- **박빛샘:** 9/7 목표는 약관 동의 전송·프로필 저장 순서, 건강정보 생성/수정, 모델 요청/조회, 작업 상태·오류, 챌린지/대시보드/기관 API 및 JSON 예시 정리. **‘뭐 했지’는 비어 있다.** 구현하지 않았다는 뜻은 아니며, 당일 완료 여부를 이 문서만으로 확인할 수 없다.
- **양준혁:** 9/7 목표는 입력 필수/선택·결측/범위·Artifact/버전·출력 의미·임계값·오류 상태 확정. 완료 공유에는 **‘오늘이, 내일이 응답 불일치에 대한 검토’**가 있다. 현재 확인 검사 우선, 미래 저위험으로 현재 위험을 취소하지 않기, 종합 점수 금지 원칙을 정리했다. 실제 불일치율·교차판정표 분석은 아직 수행되지 않았다고 명시했다. 문서의 응답 JSON은 권장안이며 확정 API 응답으로 취급하지 않는다.
- 두 분의 9/7 목표에는 모레노가 아직 포함되어 있다. 이번 MVP 제외는 최신 사용자 결정을 우선했으며 노션 원문을 대신 수정하지 않았다.

## 입력 항목 대조 — 모레노 전용으로 오인해 삭제하지 않기

| 현재 폼 항목 | 확인된 계약/용도 | 이번 처리 |
|---|---|---|
| 생년월일·성별·키·체중·흡연·음주 유무·규칙적 운동·운동일수/시간 | 기본 건강정보와 RF25 공통 요청. shared7도 공통 정보 일부 재사용 | 유지 |
| 허리둘레·혈압·주관적 건강·어제 식사 횟수 | 기본 건강정보 저장/서비스 기록 | 유지 |
| 열량·단백질·지방·탄수화물·나트륨 | 기존 KNHANES 현재 선별 22입력 계약 | 모레노 전용 아님. 최종 MVP 계약 확인 전 유지 |
| 걷기 일수·유산소 활동·음주 빈도·지역·도시/읍면·소득 분위·고혈압/당뇨 가족력 | 기존 현재 선별 22입력 계약 | 일괄 삭제하지 않음 |
| 최종 학력 | 현재 선별 22입력, shared7 및 RF25 선택 입력과 관련 | 유지. 모델별 코드 변환은 별도 계약 필요 |

근거: `experiments/diabetes_current_screening/champion_v050/inference_contract.json`, `docs/model/SHARED7_FIRST_INTERVAL_SERVICE_HANDOFF.md`, `app/prediction/contracts.py`, `app/apis/v1/health_routers.py`.

주의: RF25의 `log_household_income`과 폼의 ‘소득 분위’는 같은 값이 아니며 자동 대체하지 않는다. 가족력과 본인의 기진단도 다르다. 기존 22입력과 현재 shared7 런타임의 차이가 있어, **최종 현재 모델/스키마와 저장 API를 담당자에게 확인해야 한다.** 추가 입력 저장 API 미구현·미반영 안내는 그대로 유지한다.

## 리포트·PDF 확인 범위

현재 로컬 `app/apis/v1/wellness_routers.py`의 PDF는 상태·생활습관 기록 요약·안전 안내만 생성하며 모레노 그래프를 포함하지 않는다. 모레노 제외 때문에 백엔드 PDF를 수정하지 않았다. 기간 파라미터별 집계와 충분한 리포트 내용은 별도 미완료 항목이다.
