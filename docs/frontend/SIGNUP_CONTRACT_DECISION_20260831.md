# 회원가입 계약 불일치 및 결정 필요 사항

- 작성일: 2026-08-31
- 상태: **결정 필요 / 미확정**
- 관련 PR: [백엔드 PR #19](https://github.com/AI-HealthCare-05/AH_05_02/pull/19), [프론트엔드 PR #23](https://github.com/AI-HealthCare-05/AH_05_02/pull/23)
- 관련 담당: 박빛샘(백엔드), 이수인(프론트엔드), 정세준(PM·QA)

## 1. 발견한 불일치

기존 프론트엔드 기획에서 이메일 기반 회원가입 방식이 팀의 최종 결정으로 명시되지 않았으나, 백엔드 PR #19의 회원가입 요청은 다음 항목을 요구한다.

```json
{
  "email": "user@example.com",
  "password": "********",
  "name": "사용자 이름",
  "terms_agreed": true
}
```

이에 따라 프론트엔드가 PR #19만 기준으로 이메일·비밀번호 입력을 추가하면, 팀 합의 없이 가입 방식과 개인정보 수집 범위를 변경하게 된다.

## 2. 현재 임시 처리

- PR #19 계약에 맞춘 프론트엔드 수정안은 로컬에서만 확인한다.
- 팀 결정 전에는 회원가입 방식을 확정한 것으로 간주하지 않는다.
- 확정 전 변경은 PR #23에 최종 반영하거나 병합하지 않는다.
- API 오류 시 로컬 데모로 자동 전환하는 기능 제거는 가입 방식과 별개로 유지한다.

## 3. 팀에서 결정할 항목

### 결정 A — 이메일 기반 가입 사용

이메일을 로그인 ID로 사용하고 다음 항목을 함께 구현·정의한다.

- 이메일·비밀번호·이름·필수 약관동의 입력
- 이메일 중복 오류 처리
- 이메일 오입력 수정 방식
- 비밀번호 재설정 방식
- 이메일 인증 적용 여부
- 개인정보 처리 안내와 보유·삭제 기준
- 기존 사용자 또는 데모 사용자 계정 처리

### 결정 B — 이메일 기반 가입 미사용

기존 기획의 가입 방식을 유지하고 백엔드 계약을 변경한다.

- 사용자를 식별할 대체 필드 확정
- 로그인 또는 세션 유지 방법 확정
- `SignUpRequest`와 사용자 테이블 필드 수정
- 기존 `/auth/login` 요청 계약 수정
- 프론트엔드 가입·로그인 화면 재설계

### 결정 C — MVP 임시 계정 방식

이메일 인증 없이 이메일 문자열을 로그인 ID로만 사용하는 개발 단계 정책을 적용한다.

- 실제 이메일 발송·인증은 MVP에서 제외
- 화면에 개발용 또는 미인증 계정임을 명시
- 운영 전 이메일 인증·재설정 기능을 필수 백로그로 등록
- 실제 개인정보를 입력하지 않는 테스트 계정 규칙 마련

## 4. 프론트엔드 영향 범위

- 가입·동의 화면 입력 필드와 문구
- 기존 사용자 로그인 흐름
- 이메일 중복·형식 오류 화면
- 네트워크·서버 오류 안내
- 개인정보 및 필수 약관 표시
- 모바일·큰 글씨 화면 배치
- E2E 가입·로그인 테스트 시나리오

## 5. 백엔드·DB 영향 범위

- `SignUpRequest`, `LoginRequest` DTO
- 사용자 테이블의 이메일 필수·고유 제약
- 비밀번호 해시 및 재설정 구조
- 이메일 중복 오류 코드
- 프로필과 가입정보의 필드 분리
- 탈퇴·개인정보 삭제 정책

## 6. 회의에서 확인할 질문

1. 이메일을 실제 로그인 ID로 사용할 것인가?
2. MVP에서 이메일 인증과 비밀번호 재설정을 구현할 것인가?
3. 이름은 서비스 제공에 반드시 필요한 정보인가?
4. 성별·생년월일은 가입이 아니라 프로필·적합성 단계에서 받는 것으로 확정할 것인가?
5. 필수 약관동의와 건강정보 동의를 서로 다른 API로 저장하는 것이 맞는가?
6. 이미 생성된 개발용 계정과 데이터는 어떻게 처리할 것인가?

> 기존 프론트엔드 가입 흐름과 PR #19의 회원가입 계약이 다릅니다. PR #19는 이메일·비밀번호·이름·약관동의를 요구하지만, 이메일 기반 가입 방식은 아직 팀의 최종 결정으로 확인되지 않았습니다. 이메일을 로그인 ID로 사용할지, 다른 가입 방식을 유지하고 백엔드 계약을 수정할지 결정이 필요합니다. 결정 전 프론트 변경은 임시안으로만 유지합니다.
