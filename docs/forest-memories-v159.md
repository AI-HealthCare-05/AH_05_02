# 숲속 추억사진 · v159

## 사용자 동작

- 들판 오른쪽의 옛날 사진기를 누르면 촬영을 시작한다.
- 저장된 기본 프리셋 6벌의 실제 LPC 의상과 얼굴을 준비한 뒤, 친구들과 동물들이 잔디밭에 모인다.
- Bunbun·Last tick 토끼, 생쥐, 흰 고양이·주황 고양이·강아지, 젖소가 원본 스프라이트 동작으로 함께 등장한다.
- 촬영이 끝나면 1856×1044 PNG 한 장의 다운로드를 요청한다. 브라우저가 자동 다운로드를 막으면 결과창의 `사진 저장`으로 다시 저장할 수 있다.
- `다시 찍기`는 새 사진을 만들고, 닫기/Escape는 준비 중인 촬영을 취소한다.

| 프리셋 | 사진 속 닉네임 |
| --- | --- |
| 1 | 성실한 당근 |
| 2 | 꾸준한 당근 |
| 3 | 달빛의 빛샘 |
| 4 | 숲속의 수인 |
| 5 | 발명의 준혁 |
| 6 | 해결의 세준 |

이 이름은 촬영용 복사본에만 적용한다. 실제 계정 닉네임, 기본 프리셋 이름, 저장된 코디를 바꾸지 않는다.

## 그림과 실내 LP

`home-record-player-v159.png`와 `forest-memory-camera-v159.png`는 기존 집/숲 배경을 참조해 built-in image_gen으로 제작했다. 따뜻한 나무색과 황동, 픽셀 질감을 맞췄다. 제작 프롬프트는 [forest-memory-art-v159.json](forest-memory-art-v159.json)에 보관했다.

기존 LP 원본은 삭제하지 않았다. 실내 LP의 기존 노래 선택·재생·정지 기능을 유지하고 외관만 교체했다. 두 소품 모두 눈에 보이는 알파 영역을 런타임에 계산하고 가로세로 비율을 유지한다.

## 구현 및 안전장치

- `forest-memories.js`: 촬영용 임시 인물·동물, 사진 구도, 실제 Phaser 렌더 캡처와 원상 복원.
- `forest-game.js`: 기본 프리셋 복사, 진행/미리보기/다운로드 UI, 촬영 ID 기반 중복 방지.
- `lpc-avatar-engine.js`: 각 인물의 필수 바디·상의·하의와 선택 레이어 로딩 검증. 누락된 코디를 맨몸으로 대신 촬영하지 않는다.
- 촬영 중 이동·사냥·보상·가구 조작은 잠시 멈춘다. 기존 가구는 삭제하거나 이동하지 않으며, 인물을 가리는 가구만 촬영 동안 숨긴다.
- 완료·취소·오류·장면 종료 후 카메라, 오브젝트 표시, 입력, 애니메이션 상태를 복원한다.
- 큰 모자를 포함한 실제 의상 픽셀 상단을 측정해 이름표를 배치한다. 촬영 중 작은 화면에는 가로 구도를 중앙 정렬하고, 촬영 후 원래 화면 영역으로 돌아간다.
- 고정 사진기의 삼각대와 겹치는 가구 배치만 막으며, 주변의 꾸미기 공간은 유지한다.
- 사진에는 게임 필드만 담고, DOM 메뉴·개인정보·채팅은 넣지 않는다. 서버 업로드나 별도 영구 저장을 하지 않는다.
- 모바일 Canvas 렌더러는 메인 화면 크기에 의해 잘리지 않도록 별도 렌더 타깃 원본을 내보낸다. WebGL도 같은 출력 규격을 사용한다.
- 배포 환경에는 기존 동물 자산과 LPC 의상 팩이 필요하다. Bunbun/Last tick 원본은 각 라이선스에 따라 설치해야 하며, 이 기능은 외부 자산 이용권을 추가로 부여하지 않는다.

## 검증

- 최종 회귀 결과: Forest Node 테스트 209개, Python 테스트 56개 통과.
- 단위·통합: `node --test tests/forest-*.test.cjs`
- 기존 Python 회귀: `.venv/Scripts/python.exe -m pytest tests/test_carrot_forest_pixel_game.py -q`
- 실제 브라우저: 좁은 화면에서 사진기 클릭 → 여섯 코디와 동물 일곱 마리 → PNG 미리보기 생성, 촬영 후 기존 닉네임·100% 배율 복원 확인. 원본 이미지 점검 후 큰 모자 위 이름표가 잘리지 않도록 16:9 구도의 위쪽 여백을 확보했다.
- PC 화면에서 새 LP 외관과 기존 7곡 선택 메뉴를 확인했다. 기념사진 촬영 중/완료 화면에 브라우저 콘솔 오류가 없었다.
- 브라우저 다운로드 위치/허용 여부는 사용자 브라우저 설정에 따른다.
- 내장 브라우저 QA에서는 PNG 생성·미리보기·다운로드 파일명/링크를 확인했으나 실제 다운로드 완료 이벤트는 확인하지 못했다. 임시 링크 제거와 Blob URL 의존을 피하도록 지속형 네이티브 다운로드 링크와 검증된 PNG dataURL을 사용한다. 파일 저장 완료 여부는 실제 사용 브라우저에서 별도 확인이 필요하다.
