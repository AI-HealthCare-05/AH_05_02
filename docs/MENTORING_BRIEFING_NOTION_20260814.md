## 1. 인사 및 오늘의 목적 — 약 30초

안녕하세요. 저희는 **만성질환 생활습관 챌린지 웹서비스**를 기획하고 있는 2조입니다.

현재 Sprint 1에서 요구사항 정의서, 와이어프레임, ERD, API 명세서와 AI·데이터 계획의 1차 초안을 작성했습니다.

오늘은 산출물을 하나씩 자세히 설명하기보다는, 문서를 연결하면서 확인된 미정 사항에 대해 **MVP에서 어디까지 구현하는 것이 적절한지**, 그리고 **어떤 기준으로 결정해야 하는지** 피드백을 받고자 합니다.

## 2. 서비스 한 문장 소개 — 약 30초

저희 서비스는 사용자의 건강검진과 생활습관 정보를 바탕으로 당뇨병과 고혈압 위험군을 선별하고, 위험·보호 요인을 설명한 뒤 4주 생활습관 챌린지와 추적 대시보드를 제공하는 웹서비스입니다.

예측 결과는 의료진의 진단이나 처방을 대신하지 않으며, **위험 선별과 건강교육을 위한 정보**로 제공합니다.

## 3. Sprint 1 산출물 진행 상황 — 약 2분

먼저 요구사항 정의서입니다.

회원가입과 동의, 대상자 적합성 확인, 건강검진·생활습관 입력, 당뇨병·고혈압 위험 예측, 챌린지, 추적 대시보드, 의료기관 안내까지의 기능을 정리했습니다.

기능 요구사항뿐 아니라 의료·AI 안전, 개인정보 최소수집, 고령자 접근성, 성능, 데이터 누수 방지, 모델 재현성, 비동기 예측 처리 등의 비기능 요구사항도 포함했습니다. 각 요구사항에는 ID, 우선순위, 수용 기준, 상태와 담당자 1명을 지정했습니다.

다음은 와이어프레임입니다.

서비스 소개에서 시작해 회원가입과 동의, 적합성 확인, 건강정보 입력, AI 예측, 당뇨병·고혈압 결과, 위험·보호 요인, 챌린지 선택과 기록, 추적 대시보드로 이어지는 핵심 흐름을 구성했습니다.

고령 사용자를 고려해 큰 글씨와 높은 명암비, 한 화면에 하나의 주요 행동, 쉬운 의료용어, 충분한 버튼 크기, 색상과 텍스트·아이콘의 병행을 적용하고 있습니다.

ERD는 사용자, 동의, 적합성 확인, 건강 프로필, 건강검진, 예측 결과, 위험·보호 요인, 4주 챌린지 사이클, 일일 기록, 의료기관 권고, 추천 문구와 피드백을 중심으로 작성했습니다.

건강검진 한 건에 여러 모델 버전의 예측 결과를 저장하고, 최신 결과를 대시보드에 표시하도록 했습니다. 최초 대비 위험도 변화는 별도 컬럼에 저장하지 않고 조회할 때 계산하며, 과거 검진·예측·챌린지 기록은 덮어쓰지 않고 이력으로 보존하도록 설계했습니다.

API 명세서는 `/api/v1`을 기준으로 인증, 동의, 적합성 확인, 건강검진, 비동기 AI 예측, 챌린지, 대시보드, 의료기관 권고, 예방 행동 추천과 피드백 영역을 정의했습니다.

공통 성공·오류 응답, JWT 인증과 자원 소유권 검사, 멱등성, 페이지네이션, 모델 오류·시간 초과 처리, 민감한 건강정보의 로그 기록 금지 기준도 포함했습니다.

## 4. AI 모델 및 데이터 활용 방향 — 약 1분 30초

예측 질환은 당뇨병과 고혈압으로 설정했습니다.

국민건강영양조사는 19세 이상 모집단의 건강검진과 생활습관 변수를 활용해 현재 당뇨병·고혈압 위험군을 선별하는 데 사용합니다.

KLoSA는 중·고령자의 건강·생활습관·사회·환경 정보와 반복조사 특성을 활용해 시간에 따른 변화와 다음 조사차수의 신규 진단을 검토하는 데 사용합니다.

두 자료는 대상자와 조사 구조가 다르기 때문에 행 단위로 직접 합치지 않고, 공통 변수의 의미·단위·결측 코드·역할을 통합 메타데이터로 관리합니다.

당뇨병 모델은 두 가지 전략을 비교할 예정입니다.

- 정상·전당뇨·당뇨를 한 번에 분류하는 3클래스 다중분류
- 정상 대 전당뇨, 정상·전당뇨 대 당뇨, 정상 대 당뇨로 나눈 목적별 이진분류

연령별로는 19세 이상, 40세 이상, 65세 이상 모델을 같은 특징·분할·평가지표로 비교하고, 공통 65세 이상 검증·테스트 집단에서 고령자 성능을 확인할 계획입니다.

베이스라인 모델은 Logistic Regression, Random Forest, XGBoost 또는 LightGBM이며, AUROC·AUPRC·Macro F1·클래스별 Recall·Brier score와 calibration을 함께 보려고 합니다.

## 5. 현재 결정이 필요한 사항 — 약 1분

문서를 연결하면서 여섯 가지 핵심 미정 사항을 확인했습니다.

1. 만 19세 이상은 이용 가능 대상으로 두고, 만 65세 이상은 주 타깃으로 분리해도 되는가
2. 당뇨병과 고혈압을 같은 수준으로 구현할지, 당뇨병을 먼저 완성하고 고혈압을 확장 구조로 둘지
3. 당뇨병의 주 모델을 다중분류와 이진분류 중 무엇으로 할지
4. 3단계 분류 결과에서 대시보드의 대표 위험도와 최초 대비 변화값을 어떻게 정의할지
5. 질환별 클래스 확률과 비동기 예측 작업 상태를 DB에 어떤 구조로 저장할지
6. 기진단 사용자에게 예측을 생략하고 생활습관 챌린지를 제공해도 되는지

개인정보 측면에서는 생년월일 전체 저장 필요성, 동의 철회와 회원 탈퇴 시 건강정보의 삭제·익명화 범위도 추가로 확정해야 합니다.

## 6. 멘토에게 받을 핵심 피드백 — 약 3분

### 질문 1. 이용 대상과 주 타깃

현재 팀의 잠정안은 **만 19세 이상은 서비스 이용 가능**, **만 65세 이상은 핵심 타깃과 접근성 기준**으로 분리하는 것입니다.

이렇게 이용 자격과 핵심 타깃을 분리하는 것이 자연스러운지, 아니면 MVP에서는 65세 이상으로 이용자까지 제한하는 것이 기획과 모델 검증 측면에서 더 적절한지 의견을 부탁드립니다.

### 질문 2. 당뇨병·고혈압의 구현 깊이

현재 당뇨병 모델과 화면 흐름이 가장 구체화되어 있습니다.

저희는 당뇨병을 우선 완성하고, 고혈압은 같은 API 인터페이스와 데이터 구조로 확장 가능하게 설계하는 안을 검토하고 있습니다.

이 수준이 기업 요구에 부합하는지, 또는 두 질환을 반드시 동일한 완성도로 시연해야 하는지 확인받고 싶습니다.

### 질문 3. 당뇨병 분류 전략

저희 잠정안은 3단계 다중분류를 서비스의 주 모델로 두고, 세 가지 이진분류는 비교 실험으로 사용하는 것입니다.

위험군 선별 서비스에서 이 방향이 적절한지, 모델을 선택할 때 Macro F1, 전당뇨·당뇨 Recall, AUPRC와 calibration 중 무엇을 핵심 기준으로 삼아야 하는지도 조언 부탁드립니다.

### 질문 4. 위험도와 변화값

정상·전당뇨·당뇨 확률 중 하나를 대표 위험도로 사용하면 사용자가 실제 건강이 개선되거나 악화됐다고 오해할 수 있습니다. 모델 버전이 달라지면 과거와 최신 확률을 직접 비교하기도 어렵습니다.

초기 MVP에서는 위험도 변화보다 단계와 클래스별 확률만 표시하는 것이 안전한지, 변화값을 제공한다면 동일한 모델 버전과 같은 점수 정의 사이에서만 비교해야 하는지 확인받고 싶습니다.

### 질문 5. 예측 결과와 비동기 작업 저장

현재 당뇨병 전용 확률 컬럼을 질환별 컬럼, JSON 또는 별도 클래스 결과 테이블 중 어떤 방식으로 일반화할지 결정이 필요합니다.

또한 비동기 예측은 API에 정의했지만 ERD에는 PredictionJob 엔터티가 없습니다. Redis에는 진행 상태를 두고, DB에는 작업 ID·모델 버전·최종 상태·실패 사유·주요 시각만 최소한으로 남기는 방식이 실무와 MVP에 적절한지 의견을 부탁드립니다.

### 질문 6. 기진단 사용자 흐름

기진단자는 발병 위험 예측 대상은 아니지만 생활습관 기록 기능은 사용할 수 있습니다.

저희는 예측은 제공하지 않고, 의료진 지침을 우선한다는 안내 후 일반적인 생활습관 챌린지만 제공하는 방향을 검토하고 있습니다.

이 흐름이 의료·서비스 측면에서 적절한지, 기진단자에게는 질환 맞춤 추천을 제외하고 대시보드에도 생활습관 기록만 보여주는 것이 맞는지 피드백을 부탁드립니다.

### 질문 7. MVP 제외·후순위 기능

핵심 흐름은 `동의·적합성 확인 → 건강정보 입력 → 위험 선별 → 결과 설명 → 챌린지 → 추적 대시보드`로 보고 있습니다.

RAG·LLM 추천, 알림, 의료기관 권고 이행 확인, 고도화된 피드백과 복잡한 운영 기능은 후순위로 조정하려 합니다.

평가 기준을 충족하면서 구현 완성도를 확보하려면 반드시 남겨야 할 기능과 제외해도 되는 기능을 구분해 주셨으면 합니다.
