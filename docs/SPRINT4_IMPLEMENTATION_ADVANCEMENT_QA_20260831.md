# Sprint 4 기능 구현 고도화 QA 기준

## 1. 목적

Sprint 4는 신규 기능의 양을 늘리는 주간이 아니라, 지금까지 구현한 모델·API·DB·화면을 하나의 실행 가능한 웹서비스로 완성하는 주간이다. 핵심 사용자 흐름을 우선 통합하고 `당근의 숲`은 독립된 선택 기능 패키지로 유지한다.

## 2. 이번 주 필수 범위

1. 회원가입·동의·적합성 확인
2. 건강정보 입력·저장
3. 당뇨병 미래발병 위험 예측 작업 생성·상태 조회
4. 예측 결과·위험요인 조회
5. 챌린지 선택·일일 수행 기록
6. 대시보드·주간 리포트
7. 기진단·긴급 증상·모델 적용범위 밖 사용자 분기
8. Docker 환경 통합 실행

`당근의 숲`, 웨어러블, OCR, 식단 분류와 RAG는 핵심 흐름을 방해하지 않는 범위에서만 연결한다.

## 3. 모델–API–DB–화면 대응표

| 사용자 단계 | 화면 입력·출력 | API | DB·모델 | 완료 조건 |
|---|---|---|---|---|
| 가입 | 이메일·비밀번호·기본정보 | `POST /api/v1/auth/signup` | `users` | 최신 API 계약과 프론트 요청 필드가 일치한다. |
| 동의 | 건강정보 처리 동의 | `POST /api/v1/consents` | `consents` | 미동의 사용자는 예측을 실행할 수 없다. |
| 적합성 | 연령·기진단·긴급 증상 | `POST /api/v1/eligibility-checks` | `eligibility_checks` | 제외 사유별 다음 행동이 화면에 표시된다. |
| 건강정보 | 모델 입력값 | `POST /api/v1/health-checkups` | `health_checkups` | 모델 입력 계약에 맞는 값만 저장한다. |
| 예측 요청 | 분석 대기·진행 상태 | `POST/GET /api/v1/prediction-jobs` | `prediction_jobs`, Redis | `queued/running/succeeded/failed`가 일치한다. |
| 예측 결과 | 위험 범주·설명·안전 문구 | `GET /api/v1/predictions/{id}` | `predictions`, 모델 Manifest | 모델·스키마·임계값 버전을 추적할 수 있다. |
| 위험요인 | 승인된 설명 항목 | `GET /api/v1/predictions/{id}/risk-factors` | `risk_factors` | 미승인 결과에는 확률·개선율을 노출하지 않는다. |
| 챌린지 | 추천·선택·일일 기록 | `/challenge-recommendations`, `/challenge-cycles`, `/user-challenges` | 챌린지 관련 테이블 | 기록 저장 후 대시보드에 반영된다. |
| 대시보드 | 위험·실천 추이·주간 요약 | `/dashboard/*`, `/weekly-reports/current` | 예측·챌린지 기록 | 빈 데이터와 정상 데이터가 모두 처리된다. |
| 당근의 숲 | 공동 진행률·아바타·장식 | `/api/v1/forest/*` | `forest_*` | 건강정보 없이 수행 상태와 꾸미기 정보만 공유한다. |

## 4. 통합 순서

1. 백엔드·DB 기준 PR 반영
2. 표준 모델 추론 계약 반영
3. 프론트엔드를 최신 `develop`에 재정렬하고 API 계약 수정
4. 당근의 숲 마이그레이션 번호를 최신 번호로 재지정
5. 모델–API–프론트 E2E 검증
6. `develop → main` Release PR 생성

마이그레이션 번호는 병합 시점의 `develop`을 기준으로 다시 확인한다. 같은 번호의 마이그레이션을 동시에 병합하지 않는다.

## 5. E2E 시나리오

### 정상 흐름

- 신규 사용자가 가입하고 건강정보 처리에 동의한다.
- 적합성 확인을 통과하고 건강정보를 저장한다.
- 예측 작업을 생성하고 완료 상태까지 조회한다.
- 승인된 결과와 위험요인을 확인한다.
- 챌린지를 선택하고 오늘 수행 여부를 기록한다.
- 대시보드와 주간 리포트에 기록이 반영된다.

### 예외·안전 흐름

- 만 19세 미만: 서비스 이용 제한과 보호자·의료기관 안내
- 당뇨병 기진단: 신규 발병 예측 중단과 일반 건강관리 안내
- 긴급 증상: 예측 중단과 119·응급의료기관 안내
- 모델 적용 연령 밖: 개인화 예측 미제공과 일반 챌린지 연결
- 필수 입력 누락·범위 오류: 저장 전 항목별 수정 안내
- 모델 미탑재·추론 실패·시간초과: 실패 상태와 재시도 가능 여부 표시
- API 장애: 운영 화면에서 데모 성공으로 위장하지 않고 오류 표시

## 6. 의료·개인정보 안전 기준

- 결과는 진단·처방이 아니라 위험 선별과 건강교육으로 표현한다.
- 약물 시작·중단·용량 변경을 추천하지 않는다.
- 모델 적용범위와 성능 한계를 결과와 모델 카드에 표시한다.
- 건강정보와 예측 결과는 가족·친구에게 공유하지 않는다.
- 원본 의료 데이터, 모델 바이너리, API 키와 개인정보는 Git에 올리지 않는다.
- RAG 답변은 승인된 근거와 원문 출처를 함께 제공한다.

## 7. 담당자 인계 기준

`양준혁 모델 규격 → 박빛샘 API·DB → 이수인 화면 → 정세준 통합 QA`

각 인계에는 PR 링크, 실행 명령, 입력 예시, 정상·오류 응답, 미구현 사항을 포함한다. 매일 오후 5시 `develop` 기준으로 통합 상태를 확인한다.

- [ ] Docker 환경에서 동일 흐름을 재현한다.
- [ ] 정상·예외·의료 안전 테스트가 통과한다.
