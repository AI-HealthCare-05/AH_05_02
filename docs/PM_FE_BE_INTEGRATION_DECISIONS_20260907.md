# 9월 7일 멘토 피드백 환류 및 FE–BE–모델 통합 기준

## 1. 목적

- 멘토링 피드백을 즉시 반영·검증 필요·후순위로 구분한다.
- 프론트엔드, 백엔드, AI Worker, 모델의 계약을 하나의 기준으로 통일한다.
- 오늘이·내일이·모레노 결과가 서로 다를 때의 사용자 안내 원칙을 확정한다.
- 정상 사용자와 장애 상황을 포함한 End-to-End 검수 기준을 정한다.

## 2. 멘토 피드백 환류

| 구분 | 반영 항목 | 적용 기준 |
| --- | --- | --- |
| 즉시 반영 | 응급증상 문진 | `예/아니오` 팝업과 원터치 의료 안내를 핵심 흐름에 배치 |
| 즉시 반영 | 모델 표현 | 진단·확정이 아닌 `위험 신호 선별`과 `상담 필요성 안내`로 통일 |
| 즉시 반영 | 모델 불일치 | 모델별 목적과 기간을 구분하고 결과를 평균하거나 상쇄하지 않음 |
| 즉시 반영 | 장애 경험 | 대기·실행·완료·실패·재시도 상태를 화면에서 구분 |
| 즉시 반영 | 검증 자료 | Confusion Matrix, PPV, NPV, Positive Rate, Threshold 비교표와 Release Gate 준비 |
| 즉시 반영 | 정상 사용자 QA | 52세·전체 검진값 정상 시나리오가 중단 없이 완료되는지 확인 |
| 검증 필요 | 스마트워치 | 실제 수집 가능 항목, 동의, 갱신 주기와 서비스 효용을 조사한 뒤 범위 확정 |
| 검증 필요 | POC | 당뇨 관심군·중장년층·고령층을 대상으로 과업 성공률과 문구 이해도 확인 |
| 검증 필요 | 사진 인증 | 부정행위 방지 효과보다 입력 부담이 큰지 사용자 테스트 후 결정 |
| 검증 필요 | 3개 모델 | 현재·가까운 미래·장기 전망의 구분이 이해도와 행동 전환을 높이는지 검증 |
| 후순위 | Unity·멀티플랫폼 | 웹 MVP의 핵심 흐름과 배포 안정화 이후 별도 확장팩으로 검토 |
| 후순위 | 게임 기능 확대 | 신규 기능 추가보다 현재 화면의 사용감과 접근성 개선을 우선 |

## 3. 모델 역할과 노출 원칙

| 약칭 | 정식 명칭 | 사용자 질문 | 공개 기준 |
| --- | --- | --- | --- |
| 오늘이 | 현재 위험 신호 선별 모델 | 현재 검사·생활습관 정보에서 당뇨 위험 신호가 보이는가? | 승인된 모델만 `낮음/주의/높음`으로 표시 |
| 내일이 | 미래 신규 발병 위험 예측 모델 | 관찰 기간을 기준으로 향후 신규 발병 위험 신호가 있는가? | 승인된 예측기간과 모델 버전을 함께 표시 |
| 모레노 | 이산시간 생존모델을 활용한 연령별 발병 위험 전망 모델 | 연령·시간 구간에 따라 위험 신호가 어떻게 달라지는가? | 별도 검증 전 연구용 전망으로만 제공 |

- 서로 다른 데이터, 라벨, 관찰기간의 확률을 평균하거나 하나의 종합점수로 만들지 않는다.
- `research_candidate_only` 또는 `display_allowed=false`인 결과는 사용자에게 수치·위험범주로 노출하지 않는다.
- 낮은 결과도 질환이 없다는 뜻으로 표현하지 않으며 정기검진과 생활습관 관리를 안내한다.
- 모레노는 오늘이·내일이의 결과를 덮어쓰거나 의료 상담 필요성을 낮추는 근거로 사용하지 않는다.

## 4. 오늘이·내일이 결과 조합 안내

| 오늘이 | 내일이 | 안내 원칙 |
| --- | --- | --- |
| 높음 | 낮음 | 현재 위험 신호를 우선 안내한다. 미래 결과가 현재 검사·상담 필요성을 취소하지 않는다. |
| 낮음 | 높음 | 현재 신호는 낮지만 미래 신규 발병 위험 신호가 있음을 분리해 설명하고 예방 행동과 정기검진을 권한다. |
| 높음 | 높음 | 검사·의료기관 상담을 우선 연결하고 챌린지는 일반 건강관리 보조수단으로 제시한다. |
| 낮음 | 낮음 | 위험이 없다고 단정하지 않고 정기검진과 생활습관 유지가 필요함을 안내한다. |

공통 문구:

> 이 결과는 당뇨병을 진단하거나 치료를 결정하는 정보가 아니라, 검사와 건강상담이 필요한 위험 신호를 확인하기 위한 참고 정보입니다.

## 5. FE–BE–모델 계약 기준

| 단계 | 계약 | 확인 기준 |
| --- | --- | --- |
| 회원가입 | `POST /api/v1/auth/signup` | `email`, `password`, `terms_agreed` 전달 |
| 기본정보 | `PATCH /api/v1/users/me/profile` | 성별·생년월일 등 프로필을 가입 후 별도 저장 |
| 건강정보 | 건강검진 생성·수정 API | 모델 필수값, 선택값, 단위와 허용 범위 일치 |
| 예측 접수 | `POST /api/v1/prediction-jobs` | `checkup_id`, `model_key` 전달 후 HTTP `202`와 `job_id` 수신 |
| 상태 조회 | `GET /api/v1/prediction-jobs/{job_id}` | `queued/running/succeeded/failed` 처리 |
| 결과 조회 | `GET /api/v1/predictions/{prediction_id}` | 모델 목적·버전·표시 허용 여부에 따라 화면 분기 |

## 6. AI Worker 실패·시간초과 시나리오

1. 접수 성공 후 프론트는 `job_id`로 상태를 조회한다.
2. 상태는 `queued → running → succeeded` 또는 `failed`로 전환한다.
3. `202` 접수 이후 시간초과는 최초 요청에 `504`를 반환하지 않는다.
4. 상태 조회에서 HTTP `200`, `status: failed`, `error_code: TIMEOUT`을 반환한다.
5. 재시도 가능 시 `retryable`과 `retry_after_seconds`를 함께 제공한다.
6. 프론트는 임의 결과를 만들지 않고 실패 사유, 다시 시도 버튼, 입력 수정 경로를 제공한다.
7. 운영 DB에는 작업 상태·모델 버전·최소 오류 이력을 남기고 Redis에는 빠른 처리를 위한 최소 상태만 둔다.

## 7. 정상 사용자 E2E 검수 시나리오

대상: 52세, 기진단·응급증상 없음, 입력한 건강검진 값이 모두 정상 범위인 사용자

- [ ] 서비스 소개에서 회원가입·로그인으로 이동한다.
- [ ] 필수 약관 동의와 회원가입 요청이 정상 처리된다.
- [ ] 기본정보와 건강정보를 저장하고 누락·단위 오류가 발생하지 않는다.
- [ ] 적합성 확인을 통과하고 오늘이·내일이 작업이 각각 생성된다.
- [ ] 작업 상태가 완료될 때까지 로딩·재시도 UI가 정상 동작한다.
- [ ] 낮은 위험 신호가 나오더라도 `정상 확정`, `질환 없음`으로 표현하지 않는다.
- [ ] 승인되지 않은 모델의 확률·범주는 숨긴다.
- [ ] 결과 확인 후 챌린지와 대시보드로 중단 없이 이동한다.
- [ ] 사용자가 건강정보를 수정하고 다시 선별·예측할 수 있다.

## 8. 주간 완료 기준(Definition of Done)

- [ ] FE 요청 DTO와 BE 스키마·상태값·오류 코드가 일치한다.
- [ ] 오늘이·내일이가 동일 검진 입력으로 실제 Worker를 거쳐 결과를 저장한다.
- [ ] 승인·연구용 결과의 화면 노출 정책이 적용된다.
- [ ] 정상·모델 불일치·결측·범위 오류·Worker 실패·시간초과 시나리오를 검증한다.
- [ ] 오늘이·내일이 Confusion Matrix와 Threshold별 Recall·Specificity·PPV·NPV·Positive Rate를 제출한다.
- [ ] Model Release Gate의 통과·보류 사유를 기록한다.
- [ ] 실제 Model Artifact를 사용하는 E2E 시연과 배포 실패 테스트 결과를 남긴다.
- [ ] API·요구사항·안전 문구·실행 가이드를 코드와 함께 갱신한다.

## 9. PR 분리 및 통합 기준

- 한 PR에는 하나의 책임만 담는다: 인증, 모델 런타임, 프론트 흐름, E2E 테스트, 문서 중 하나.
- 현재 기능 PR은 `codex/e2e-integration`을 기준으로 검증한 뒤 `develop → main` Release PR로 반영한다.
- 핵심 의료 흐름과 당근의 숲 확장팩을 같은 PR에 섞지 않는다.
- 테스트·실행 방법·미구현 사항·의료 안전 영향을 PR 본문에 기록한다.
- 원본 의료 데이터, 대용량 모델, 개인정보, 비밀키는 커밋하지 않는다.
